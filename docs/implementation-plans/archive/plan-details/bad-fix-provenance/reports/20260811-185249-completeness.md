Step 3 can therefore treat a note added after the newest recurrence as an intervening remedy.
  - Fix: Persist each annotation’s recording time and source in the existing annotation store, require it to predate the recurring pass, treat undated legacy notes as insufficient, and retain it through collapse for rendering.
- HIGH `[remedy-note-evidence]`: The Architecture says “Notes remain operator-authored evidence,” but `completeness_apply_parallel.annotation_status` persists `("applied", "APPLIED")` for every automated success. Step 3 (`Add the bad-fix provenance advisory to convergence`) would count and render that generated status token as a remedy note, producing false bad-fix advice.
  - Fix: Define qualifying remedy-note evidence for every producer so generated status or output text never triggers the advisory and only explicit operator remedy text qualifies.
- MEDIUM `[drift-halt-provenance]`: Step 3 (`Add the bad-fix provenance advisory to convergence`) promises that `halt_reason="drift"` never triggers, but its Architecture and acceptance predicate requires only `status=applied` plus a non-empty note. `Annotation` permits that status/halt-reason combination, so the stated exclusion is not enforced.
  - Fix: Require qualifying remedy evidence to have an empty halt reason and test every allowed status/halt-reason combination.
- MEDIUM `[shared-title-helper]`: Step 3 (`Add the bad-fix provenance advisory to convergence`) requires a “Shared title helper with `_matches` tier-3 fuzzy title only,” but `convergence_diagnosis._matches` currently owns that title comparison. Extracting it preserves existing behavior while the new classifier adds behavior, so this feature step mixes a refactor with the advisory feature.
  - Fix: Split the title-match extraction into a behavior-preserving refactor step that the bad-fix feature step depends on.
- MEDIUM `[same-issue-identity]`: Step 3’s `Same-issue identity` calls equal ids a priority-0 “first-decisive” fast path, yet the same section says finding ids “never [are] the sole identity”; Acceptance criteria repeats the first-decisive rule. The matcher therefore has no single rule for whether equal ids alone can trigger an advisory.
  - Fix: State one equal-id rule and use it consistently across the identity tiers, acceptance criteria, and fixtures.
