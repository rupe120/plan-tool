# Step 2 — Make `install-skill` install the router and `DIRECTIVES.md` as one set

<!-- plan-tool:detail-format-version: 1 -->

## Summary

`plan_tool/cli/skill_cmd.py:cmd_install_skill` writes exactly one destination path today (`dest = dest_dir / "SKILL.md"`). This step makes it write two: the per-integration `SKILL.md` router plus a sibling `DIRECTIVES.md` copied or symlinked in from the single shared source at `integrations/shared/DIRECTIVES.md`, so the installed router can cite its reference by bare relative name under both install modes. The command gets a two-phase shape — check every destination in the set for a foreign collision before writing any of them, then write only the paths that actually need it, skipping any path that's already correctly installed and unlinking only the paths `--force` actually needs to clear. `_bundled_skill_source` and the idempotency/collision logic that already exist for the single-file case generalize to run once per path in the set rather than being duplicated. On green, every `install-skill` invocation (symlink, `--copy`, `--user`, either `--root`) installs both files together, a foreign file at either path blocks the whole set without `--force`, and an upgrade from the single-file installer (an existing correct `SKILL.md`, no `DIRECTIVES.md` yet) installs only the missing file.

## Why

`integrations/shared/DIRECTIVES.md` is already the tracked, canonical reference (per the plan's Architecture section), and the plan's settled decision is that the installer carries it into the skill directory as a **sibling** of the router — a bare relative link resolves under both a symlink install and a `--copy` install, where a `../../`-style link would not. Today's installer has no notion of a second path at all: `_bundled_skill_source` resolves only the per-integration `SKILL.md`, and `cmd_install_skill`'s idempotency/collision/`--force` logic (`already` check, `dest.unlink()` under `--force`) is written entirely in terms of one `dest`.

The concrete case that makes "skip paths that are already correct" more than an optimization: an operator who ran `install-skill` before this step lands already has a correctly-symlinked (or copied) `SKILL.md` and no `DIRECTIVES.md` at all. Re-running `install-skill` after upgrading must install the now-missing `DIRECTIVES.md` without touching the already-correct `SKILL.md` — naively looping the existing single-file logic per path already gets this right by accident (each path's idempotency check is independent), but the collision-refusal and `--force` behavior do not generalize for free: refusing on the *first* colliding path found would leave the other path unvisited (and, if it happens to run after a partial write, half-installed), and a `--force` that unconditionally unlinks every destination in the set would tear down and relink a `SKILL.md` that was already correct, which is unnecessary churn on a path nothing was wrong with.

## Implementation

**Two bundled sources instead of one.** `_bundled_skill_source(integration)` (`plan_tool/cli/skill_cmd.py`) already resolves `integrations/<integration>/SKILL.md` via `_packaged_integrations_dir()`. Add a sibling resolver for the shared reference — `integrations/shared/DIRECTIVES.md` — following the same shape (`None` when `_packaged_integrations_dir()` is `None` or the file is absent, so a broken install is diagnosed the same way for either file). The shared reference is a single file used by every integration; it is not per-integration like `SKILL.md`.

**Represent the install as an ordered set of (name, source, dest) items, not two hand-duplicated blocks.** `cmd_install_skill` builds `dest_dir` once (as it does today), then a small ordered sequence pairing each bundled source with its sibling destination under `dest_dir` — `SKILL.md` first, `DIRECTIVES.md` second (or whatever order reads best; order only matters for message ordering, not correctness, since the whole set is checked before anything is written). This is the shape that makes "check every path before writing any" and "skip paths already correct" naturally fall out of one loop instead of being reasoned about twice.

**Missing bundled source stays a hard failure, for either file.** If either resolver returns `None`, report the error and return `1` before touching `dest_dir` at all — mirrors today's `source is None` branch, just checked for both sources. `tests/cli/test_skill_cmd.py::test_missing_bundled_source_returns_1` already exercises the `SKILL.md`-missing case by pointing `_packaged_integrations_dir` at an empty directory (which makes *both* resolvers return `None`); add the sibling case where `SKILL.md` resolves but `DIRECTIVES.md` doesn't (see Tests).

**Phase 1 — classify every destination before writing any of them.** For each item in the set, compute one of three states using the same per-item logic `cmd_install_skill` already has for the single file (the `_resolve_or_none` / `_same_bytes` idempotency check, generalized to take `(source, dest)` rather than closing over the one pair):

- **already-correct** — a symlink resolving to the item's own source, or (non-symlink) a file with byte-identical content. Report `info(f"already installed: {dest}")` and take no further action on this item in phase 2.
- **missing** — `dest` does not exist and is not a symlink. Always installed in phase 2, regardless of `--force`.
- **foreign-collision** — `dest` exists (or is a symlink) and is neither of the above.

Collect every foreign-collision item before deciding anything. If any exist and `--force` was not passed, report the error and return `2` **without writing any item in the set** — including the ones that were missing or already-correct. This is the "one bad path blocks the whole set" invariant the step title asks for: it stops a run from silently completing a partial install (e.g. correctly linking `SKILL.md` while refusing on `DIRECTIVES.md`) that a later idempotency check would then read back as fully correct. Name every colliding destination path in the error, not just the first — consistent with this repo's existing rule for multi-item checks (report every offender, not the first one found).

**Phase 2 — write only what needs writing.** With no unresolved collision (either none existed, or `--force` was passed):

- Skip **already-correct** items entirely — no `unlink`, no re-`symlink`/re-`copyfile`, no directory churn beyond `dest_dir.mkdir(parents=True, exist_ok=True)` (safe to call unconditionally; it's a no-op when the tree already exists).
- For **missing** items, install directly (symlink or copy, per `args.copy`, exactly as today's single-item branch does).
- For **foreign-collision** items (only reachable under `--force`), `unlink()` first, then install. This is "limit `--force`'s unlink to the paths that collide": a `--force` run whose only collision is `DIRECTIVES.md` must not touch a `SKILL.md` that was already correct — it lands in the already-correct branch above and is never unlinked.

Report success per item the same way the single-file version does today (`success(f"linked skill → {dest}")` / `success(f"copied skill → {dest}")`), plus the existing `location:` / stale-copy-warning / machine-local-symlink-warning info lines. Keep the overall return code `0` whenever the set finishes with no unresolved collision, whether that meant writing both items, one, or (all-already-correct) neither.

**What does not change:**
- `--user`, `--root`, `--integration`, and `--copy` keep their existing meaning and argparse wiring (`register()`); this step does not touch `--integration`'s choices (`("claude", "codex")`) or add a `cursor` value — that's step 4, gated on this step landing first per `depends_on`.
- The module stays a leaf: still only `plan_tool.cli.context`, `plan_tool.backend._packaged_integrations_dir`, `plan_tool.cli.parser.Handler`, and `plan_tool.style` — no new imports needed for this change.
- No new argparse flags. If the `--force` help string changes to describe per-path scope (recommended, since "overwrite an existing skill file that points elsewhere" no longer describes the set-wide behavior), regenerate `docs/cli/install-skill.md` and, if the subcommand's own `help=` changes too, `docs/cli/README.md` — both are generated from the live parser (`plan_tool/cli_reference.py`) and must never be hand-edited; `tests/cli/test_cli_reference.py` fails on any diff between the committed files and a fresh render.

**Known pre-existing edge case, not addressed here:** a destination path that is a directory rather than a file behaves inconsistently today (refused without `--force` since `_same_bytes` catches the `OSError` and falls through to the collision branch, but `dest.unlink()` under `--force` would raise `IsADirectoryError` on a real directory). This step does not change that behavior for either path in the set — see [Deferred](#deferred).

## Acceptance criteria

- `plan-tool install-skill` (symlink, default root/integration) installs both `<root>/skills/plan-tool/SKILL.md` and `<root>/skills/plan-tool/DIRECTIVES.md`, the latter a symlink resolving to `integrations/shared/DIRECTIVES.md`.
- `plan-tool install-skill --copy` embeds both files' bytes at the destination (neither is a symlink).
- `plan-tool install-skill --user` and `--root .agents` install both files under the selected base, exactly as they do today for `SKILL.md` alone.
- A foreign file at either destination path, without `--force`, returns `2`, leaves every destination in the set untouched (including a destination that had no collision), and the error names every colliding path.
- `plan-tool install-skill --force` unlinks and reinstalls only the destination paths that actually collided; a destination that was already correctly installed is not unlinked, re-symlinked, or re-copied.
- Running `install-skill` when one destination is already correct and the other is missing (the upgrade case) installs only the missing one and leaves the correct one's symlink target/inode unchanged.
- A missing bundled shared-reference source (broken install) returns `1` and writes nothing, the same as a missing bundled router source does today.
- `tests/cli/test_skill_cmd.py` and `tests/test_backend.py::test_packaged_integrations_dir_finds_real_manifests` pass with the extensions above.
- `docs/cli/install-skill.md` and `docs/cli/README.md` match a fresh `python -m plan_tool.cli_reference --write` render (`tests/cli/test_cli_reference.py` stays green).
