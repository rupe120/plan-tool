Ordinary concept anchors need not carry a step, so the signal cannot reliably name the concentrated arm required by the override rule.
  - Fix: Persist typed affected-step or arm attribution for clustering-eligible findings, and emit no arm advice when attribution is unknown.
- HIGH `[check-saturation-denominator]`: Step 4 (`Add calibrated check-saturation advice to audit reports`) calls saturation “a count over persisted findings,” but `Recommendation` and `SavedReview` persist only fired findings, not the artifacts a source examined and found clean. Without an eligible-artifact denominator and one result per target, the design cannot distinguish “every applicable artifact” from a partial set of firings.
  - Fix: Persist each source’s eligible target inventory and per-target evaluation outcome before reporting saturation.
- HIGH `[calibration-release-order]`: Architecture says “The five shapes and their classification are settled,” and Acceptance criteria say “The three checked shapes emit advisory, evidence-bearing signals,” but Architecture also says “If a checked shape has a high false-positive rate ... classify it judgment-only.” Step 7 (`Record saved-report calibration evidence and close BACKLOG #224`) is non-code and follows steps 2–5; legacy sidecars are provenance-unknown, so self-seeded has no usable new-form history before its reporter ships.
  - Fix: Put a reviewed calibration decision, including its evidence rule and insufficient-history outcome, before finalizing the registry, emitters, and fixed-classification criteria.
- HIGH `[per-report-persistence-order]`: Step 3 (`Replace the taper warning with calibrated arm-clustering advice`) promises a round-two prompt while Architecture limits checked shapes to “data already persisted.” `plan_tool/cli/completeness_phases:_persist_and_present_report` builds the report before `plan_tool/completeness_report:write_completeness_report` saves its sidecar, so reading only saved data delays the signal past the current round.
  - Fix: Specify a raw-snapshot, persistence, evaluation, and rendering order that lets the current report fire immediately without reading unpersisted evidence.
- HIGH `[self-seeded-history-ancestry]`: Step 5 (`Add calibrated self-seeded finding advice to audit reports`) treats clean, available revisions as comparable but never requires the prior report’s HEAD to be an ancestor of the current one. After a rebase or branch switch, `previous..current` lists commits reachable only from the current revision, not changes since the prior report, so the fail-closed signal can make a false provenance claim.
  - Fix: Require an ancestor relationship between saved boundaries and mark divergent history provenance-unknown with no advice.
- HIGH `[self-seeded-attribution]`: Step 5 (`Add calibrated self-seeded finding advice to audit reports`) treats a current citation intersecting any commit since the prior report as a self-seeded loop. That proves only that the region changed; it does not link the commit to a prior finding or its apply outcome, so unrelated user or planned edits fire the same advice.
  - Fix: Require a persisted link from the current citation through a prior cited finding and recorded apply outcome to the intervening commit; otherwise leave provenance unknown and emit no self-seeded advice.

## Conceptual completeness — reported, not auto-applied

Coverage gaps in the plan's own ideas are reported for visibility in this bare-plan audit. Apply actions are withheld until a complete detail bundle exists, so these findings are informational for now.

- HIGH `[typed-citation-source]`: Step 1 (`Persist typed finding citations and report revisions in audit history`) defines validation for typed citations but never identifies an audit producer or output field that supplies one. At HEAD, `plan_tool/prompts/plan-audit.md` asks for symbolic anchors “not line numbers,” and `plan_tool/review.py:check_plan_audit` persists only title, body, and anchor; generic prose is explicitly forbidden as a fallback, leaving step 5 with no real positive input.
  - Fix: Define the typed citation output contract for every finding producer eligible for self-seeded analysis and require it to be parsed before persistence.
- HIGH `[report-boundary-race]`: Step 1 (`Persist typed finding citations and report revisions in audit history`) says each report records the HEAD it audited but does not define capture timing or a recheck before save. A commit or worktree change during a model audit can leave a clean later boundary attached to evidence read from an earlier state, corrupting the exact Git comparison.
  - Fix: Capture the boundary before audit inputs are read and mark the report provenance-unknown if HEAD or cleanliness changes before persistence.
- MEDIUM `[self-seeded-commit-intersection]`: Step 5 (`Add calibrated self-seeded finding advice to audit reports`) promises “commits that intersect” a cited line region, but it does not define how a multi-commit range maps each commit’s hunks to the cited region. A path-limited `git log previous..current -- path` only proves that a commit touched the file, so listing it as region-intersecting would overclaim.
  - Fix: Define per-commit hunk-to-region attribution and cover shifted line ranges across multiple commits in the saved-history tests.
- HIGH `[calibration-evidence]`: Steps 3–5 promise thresholds “calibrated against saved report history,” but the Architecture never defines a report window, operator verdicts, or a rule that turns history into a threshold or false-positive rate. At HEAD, `review_persistence.SavedReview` stores recommendations and annotations, not shape correctness verdicts, and step 7 records evidence only after the emitter steps need their thresholds.
  - Fix: Define a pre-emitter calibration protocol with a named report sample, recorded operator judgments, threshold selection, and a kill-or-reclassify decision for each checked shape.
- HIGH `[saved-review-data-contract]`: Step 1 (`Persist typed finding citations and report revisions in audit history`) adds persisted fields to `Recommendation` and `SavedReview`, but no step updates `DATA_CONTRACT.md`. At HEAD, `plan_tool/data_contract.py:persisted_dataclass_contracts` registers both types and `tests/test_data_contract.py:test_every_persisted_field_is_documented_in_own_section` fails when a registered field lacks that document, so the shipped schema would violate its required contract.
  - Fix: Include the new citation and revision-boundary fields in the saved-review data contract, including their legacy/unknown meaning.
