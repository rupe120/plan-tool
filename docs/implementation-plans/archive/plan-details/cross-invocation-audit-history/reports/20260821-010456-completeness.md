The reader can therefore classify reports whose finding sets came from different audit settings.
  - Fix: define the full durable compatibility key, treat any unknown member as `identity-uncertain`, and cover each incompatible setting in the fixture matrix.
- HIGH `[anchor-identity]`: Step 2's exact-anchor rule does not define a one-to-one match when an anchor repeats. `## Architecture`, `## Input`, `## Testing`, and the acceptance criteria call anchors reliable, but `DATA_CONTRACT.md` says they are encouraged rather than guaranteed stable, and `create-default-test-command/reports/20260817-203245-completeness.json` contains two different findings with `marker-table-boundary`; matching by that anchor can pair the wrong concerns and report a false severity change.
  - Fix: require a one-to-one anchor match and make duplicate, missing, or changed link keys `identity-uncertain` with every affected raw id shown.
- HIGH `[saved-evidence-order]`: `## Architecture`, `## Input`, `## Risks`, step 1, and step 2 require legacy and malformed evidence to stay visible and non-confirming, yet they do not say how such a record orders the timeline or whether it blocks comparison across it; `## Testing` and the acceptance criteria omit both states. At HEAD, `load_report_history` drops `ReviewLoadError` sidecars and sorts an invalid `created_at` last, so an implementation could skip a bad middle record and compare reports that were not adjacent saved evidence.
  - Fix: define a total order and a no-bridge rule for legacy, malformed, and invalid-timestamp records, rendering each affected pair as `identity-uncertain` with visible file evidence and fixture coverage.
- MEDIUM `[pairwise-trajectory-states]`: `## Overview` and `## Architecture` promise a severity-classified positive or negative trajectory, while step 2 supplies comparison, step 3 supplies rendering, and step 4 documents states; none defines the comparable-pair states for added, removed, unchanged, or severity-changed findings, nor the output for a history containing both reliable and uncertain pairs. Those choices yield materially different operator conclusions while all satisfy the current acceptance text.
  - Fix: name the pair result states, severity-delta rules, and mixed-history rendering, then bind steps 2–4, tests, documentation, and acceptance criteria to them.
- MEDIUM `[existing-convergence-isolation]`: Step 3 promises unchanged existing advisories, telemetry, and exit codes, and `## Overview` promises no exit-code change, but `## Testing` and the acceptance criteria only preserve advisories. `cmd_convergence` records telemetry with `runs=len(history.runs)` after `load_report_history`, so adding visible legacy or malformed evidence to that history can change telemetry or the existing diagnosis even if the new section renders separately.
  - Fix: define the separate base-history boundary and add acceptance and regression coverage for unchanged existing diagnosis, advisories, telemetry count, and always-zero exit behavior.
- MEDIUM `[identity-coverage-meaning]`: `## Overview` and `## Architecture` require `identity-uncertain` “with coverage,” `## Input` names saved audit coverage, and step 3’s dependency note calls step 2’s result “identity coverage.” The plan never defines whether the rendered value is sampling coverage or a finding-match rate, nor its denominator, so operators can receive materially different coverage values from compliant implementations.
  - Fix: define one operator-facing identity-coverage measure, distinguish it from saved sampling coverage, and test its value for uncertain pairs.
- MEDIUM `[empty-audit-history-state]`: `## Architecture`, step 2, step 3, `## Testing`, and the acceptance criteria define the one-report case but not the case where a plan has no saved completeness report. `plan_tool/convergence_diagnosis.py:render_diagnosis` already has a `no-history` result, while the new section could reasonably render either that state or `identity-uncertain`, leaving documentation and tests unable to verify the output.
  - Fix: define the zero-report history state, its operator guidance, and its acceptance test.
