# `plan-tool detail`

## Usage

```
plan-tool detail [-h] [-y] [--max-iterations N] [--iteration-budget SECONDS] [--time-budget SECONDS] [--max-stall-rounds N] [--allow-drift] [--no-auto-reconcile-on-drift] [--no-triage] [--include-info] [--no-collision-sidecar] [--iterate | --no-iterate | --detail-only | --reconcile] [--step STEP] [--jobs N] [--all] [--force] [--dry-run] [--recover-refused] [--grade {run,jira}] [--split | --no-split] [--lessons | --no-lessons] [--no-resume] [--no-completeness] [--commit] [--reuse | --no-reuse] [--reuse-id STEM] name
```

## Arguments

| Argument | Description |
| --- | --- |
| `name` | plan name — slug, filename stem (e.g. 1-my-feature), or filename.md |

## Options

| Option | Default | Description |
| --- | --- | --- |
| `-y`, `--yes` | off | auto-accept Y/N confirmation prompts (proceed with the offered action without asking). Useful for scripted/unattended runs. |
| `--max-iterations` `N` | `3` | cap the convergence loop at N iterations even if findings keep changing (default: 3). Ignored when --no-iterate is set. |
| `--iteration-budget` `SECONDS` | `1800` | debounced no-progress deadline in seconds: stop the convergence loop only once SECONDS pass with no forward progress at all (default: 1800). Resets on every round and every apply_finding call, so one long claude call — even 15-20+ minutes — never trips it on its own; see --time-budget for a true total-elapsed cap. Ignored when --no-iterate is set. |
| `--time-budget` `SECONDS` | — | cooperative wall-clock cap (#123): stop the convergence loop cleanly at the next round boundary once SECONDS of total elapsed time pass — even while still converging — so a long op lands before an external execution ceiling instead of being killed mid-call. Exits 0 with a resume hint. Unlike --iteration-budget (a no-progress stall deadline), this is a hard total-elapsed cap. Falls back to PLAN_TOOL_TIME_BUDGET; default off. Ignored under --no-iterate. |
| `--max-stall-rounds` `N` | `2` | stop the convergence loop after N consecutive rounds whose open-finding count fails to shrink (default: 2). This is the ID-agnostic backstop for a subjective claude audit that re-phrases the same findings each round (fresh ids defeat the marginal / converged checks). Pass 0 to disable. Ignored when --no-iterate is set. |
| `--allow-drift` | off | opt back into the legacy 'warn but proceed' behavior when a watched file's content changes mid-iteration. Default: the loop checks drift BEFORE each apply (halts without spending claude tokens if drift detected) AND AFTER (keeps the apply's edits but halts subsequent applies if drift happened during the apply call). Token-preserving by design -- no revert, just halt + flag for `git diff` review (task #30). Pass --allow-drift only when you're sure the drift is expected (e.g. an automated formatter touching files in step.files during iteration). |
| `--no-auto-reconcile-on-drift` | on | skip the auto-reconcile pass that fires when drift halts the iteration loop. Default: when drift is detected, plan-tool runs `reconcile` against the step(s) that own the drifted file(s), saves the findings, and prints a structured summary inline with the halt (Lesson 13: audit beats observe). Pass this flag to suppress that extra claude call -- useful in CI runs that prefer a minimal stderr footprint, or when you'll inspect drift manually via `git diff` and `plan-tool run --mode reconcile`. |
| `--no-triage` | on | skip the impact-weighted triage gate on findings. Default: when a finding carries impact/complexity tags (the plan-audit prompt's trailing ``(impact=…, complexity=…)`` on conceptual findings; the reconcile prompt's ``Impact:`` / ``Complexity:`` fields), the iteration loop skips applies whose complexity strictly exceeds their impact (low+medium, low+high, medium+high) -- those findings are reported on stderr and dropped from the open-set so convergence short-circuits when only triaged findings remain. Findings without triage tags (deterministic checks, untagged output) default to apply. Pass this flag to force-apply every finding regardless of triage tags -- useful for completeness sweeps where you want to land every applicable edit. |
| `--include-info` | off | apply info-severity findings too. Default: info findings are advisory (a concept too vague to audit, a heuristic hit, a detail-only path) and are excluded from the apply loop -- they're still reported in the deferred summary, just not auto-applied. Pass this to spend claude tokens applying them as well. |
| `--no-collision-sidecar` | on | skip the change-collision sidecar pause when drift fires during apply_finding. Default: when drift is detected post-apply, plan-tool saves claude's edits to `<stem>-change-collision<ext>` next to each modified original, restores originals to pre-apply state, and pauses interactively for the user to merge with their preferred tool (vimdiff, `code --diff`, meld, etc.). Pressing Enter at the prompt continues the iteration loop against the merged state; Ctrl-D / typing 'abort' halts as today. Pass this flag to revert to the legacy 'keep claude's edits on disk, review via git diff' behavior -- useful when scripting or piping to a CI consumer that doesn't expect sidecar files. Headless runs (-y or non-TTY) auto-skip the pause and fall through to halt regardless of this flag, since there's no human to merge. |
| `--iterate`, `--no-iterate` | off | run the per-step detail-quality review + apply loop after each detail-file write. Default OFF for detail -- pass --iterate to opt in (the default emits the one-shot write only). With the default max-iterations cap, detail scales the effective per-step iteration cap by complexity: low=1, medium=2, high/unknown=3. |
| `--detail-only` | off | write detail files without the per-step detail-quality loop, then run the whole-plan completeness tail with auto-update. Use this explicit bulk-speed mode when you want to defer grounding to the final pass; incompatible with --no-completeness. |
| `--reconcile` | off | audit the plan's per-step detail markdown against the code on disk (treats code as canonical). Mutually exclusive with the authoring path; renders prompts/detail-reconcile.md and walks findings via the apply-finding handler. Requires --step or --all. |
| `--step` `STEP` | — | generate for one step by id (default: every step lacking detail) |
| `--jobs` `N` | `1` | run up to N per-step authoring calls concurrently (explicit integer >= 1; default 1 = serial; there is no 0/auto mode). N>1 requires --no-iterate --no-split and is incompatible with --lessons (lesson capture needs a clean --iterate converge, which is serial-only). Ignored on the --reconcile audit path. |
| `--all` | off | with --reconcile: sweep the per-step audit across every step not yet done (done steps are skipped — their detail is a historical record of delivered work). One claude call per step; halts on the first per-step failure. Mutually exclusive with --step. |
| `--force` | off | overwrite an existing detail file and replace its `detail:` pointer (default: skip steps that already have a detail file) |
| `--dry-run` | off | render the prompt(s) and print them; do not invoke claude or write anything |
| `--recover-refused` | off | targeted recovery for one detail file the shared format-version reader gate refuses (an unsupported/malformed marker) or that has no valid carrier H1. Requires the exact companion shape --step N --force --no-completeness: archives and replaces only the named step's file, without reading any other detail file in the bundle (sibling, already-implemented, or deterministic-grounding) and without running the post-write convergence loop or the whole-bundle completeness tail. Re-run per refused target, then a fresh `completeness-audit` once every target is repaired. Ordinary --force re-authoring, merge, and forced review regeneration are unaffected — none of them set this. |
| `--grade` `{run|jira}` | `run` | detail authoring grade (default: run). Only the run grade can author new detail. `jira` remains accepted solely to return a clear retirement error; existing Jira-grade details remain readable only through explicit consumer selectors. |
| `--split`, `--no-split` | on | after authoring, offer to split any step the purity self-check flags as mixed (refactor + feature) into a refactor-then-feature pair and re-author both halves (default: on). Interactive only (each split is confirmed y/N) and skipped for any step whose downstream is done. Pass --no-split to only surface mixed steps as a warning. |
| `--lessons`, `--no-lessons` | off | capture lessons learned (default: off). When on, after a step's detail-quality iterate loop exits with 0 open findings, a second claude call distills new general lessons into ~/.plan-tool/lessons/general.md and project-specific lessons into <repo_root>/.plan-tool/lessons/project.md. Requires --iterate (capture never runs from an unaudited first write). Off by default because it costs an extra claude call per step; pass --lessons to opt in. --no-lessons is the explicit form of the default. |
| `--no-resume` | off | ignore any saved checkpoint under <repo_root>/.plan-tool/checkpoints/<slug>/ and re-invoke claude for every step. By default, when a checkpoint's input hash matches the current step's title/files/depends_on, the cached body is reused (and confirmed interactively on a TTY). Pass this to force fresh generation, e.g. after an out-of-band template/prompt change that doesn't alter the step's frontmatter. |
| `--no-completeness` | on | skip the conceptual completeness pass that runs after a clean authoring run. Default: once the detail files are written, plan-tool runs `completeness` against the whole plan — a single plan-audit claude call plus deterministic well-formedness checks — surfacing cross-step contradictions, material ambiguities, and orphaned concepts the per-step detail-quality loop can't see, and (when --iterate is passed) applying the deterministic well-formedness findings. Conceptual ambiguity is reported with correctness, and both it and completeness gaps are persisted unapplied for a session-directed edit (#85). Pass this flag to suppress the tail entirely; without --iterate (the default) the tail is an audit-only report with no apply calls. |
| `--commit` | off | after a clean authoring run (and the completeness tail), stage all changes (git add -A) and create one commit with subject 'plan(<slug>): detail — authored N step(s)'. Requires a clean working tree up front; off by default; ignored under --dry-run or when nothing was authored. |
| `--reuse`, `--no-reuse` | — | for --reconcile: reuse a saved detail-reconcile's findings instead of running a fresh claude audit, when the save is fresh (plan AND code fingerprints still match). Default (unset): prompt interactively, auto-accepting under --yes / non-TTY stdin. --reuse always reuses a fresh save; --no-reuse always re-audits. A stale save is never reused — it declines to a fresh audit with a staleness note. |
| `--reuse-id` `STEM` | — | pin reuse to a specific saved detail-reconcile by filename stem (the bare `<ts>` or full `<ts>-detail-reconcile` form); default: newest matching save for this step. An unresolved id prints a note and falls back to a fresh audit. Not compatible with --all (a pinned save can't mean anything sensible across every step). |
