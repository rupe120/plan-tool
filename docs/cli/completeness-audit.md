# `plan-tool completeness-audit`

## Usage

```
plan-tool completeness-audit [-h] [-y] [--max-iterations N] [--iteration-budget SECONDS] [--time-budget SECONDS] [--max-stall-rounds N] [--allow-drift] [--no-auto-reconcile-on-drift] [--no-triage] [--purity | --no-purity] [--include-info] [--no-collision-sidecar] [--fail-on-findings] [--iterate | --no-iterate] [--json] [--audit-passes N] [--audit-samples N] [--reuse-audit | --no-reuse-audit] [--reuse-audit-id STEM] [--audit-dry-rounds N] [--commit] name
```

## Arguments

| Argument | Description |
| --- | --- |
| `name` | plan name — slug, filename stem (e.g. 1-my-feature), or filename.md |

## Options

| Option | Default | Description |
| --- | --- | --- |
| `-y`, `--yes` | off | auto-accept Y/N confirmation prompts (proceed with the offered action without asking). Useful for scripted/unattended runs. |
| `--max-iterations` `N` | `3` | cap the convergence loop at N iterations even if findings keep changing (default: 3). Ignored when --no-iterate is set. |
| `--iteration-budget` `SECONDS` | `1800` | debounced no-progress deadline in seconds: stop the convergence loop only once SECONDS pass with no forward progress at all (default: 1800). Resets on every round and every apply_finding call, so one long claude call — even 15-20+ minutes — never trips it on its own; see --time-budget for a true total-elapsed cap. Ignored when --no-iterate is set. |
| `--time-budget` `SECONDS` | — | cooperative wall-clock cap (#123): stop the convergence loop cleanly at the next round boundary once SECONDS of total elapsed time pass — even while still converging — so a long op lands before an external execution ceiling instead of being killed mid-call. Exits 0 with a resume hint. Unlike --iteration-budget (a no-progress stall deadline), this is a hard total-elapsed cap. Falls back to PLAN_TOOL_TIME_BUDGET; default off. Ignored under --no-iterate. |
| `--max-stall-rounds` `N` | `2` | stop the convergence loop after N consecutive rounds whose open-finding count fails to shrink (default: 2). This is the ID-agnostic backstop for a subjective claude audit that re-phrases the same findings each round (fresh ids defeat the marginal / converged checks). Pass 0 to disable. Ignored when --no-iterate is set. |
| `--allow-drift` | off | opt back into the legacy 'warn but proceed' behavior when a watched file's content changes mid-iteration. Default: the loop checks drift BEFORE each apply (halts without spending claude tokens if drift detected) AND AFTER (keeps the apply's edits but halts subsequent applies if drift happened during the apply call). Token-preserving by design -- no revert, just halt + flag for `git diff` review (task #30). Pass --allow-drift only when you're sure the drift is expected (e.g. an automated formatter touching files in step.files during iteration). |
| `--no-auto-reconcile-on-drift` | on | skip the auto-reconcile pass that fires when drift halts the iteration loop. Default: when drift is detected, plan-tool runs `reconcile` against the step(s) that own the drifted file(s), saves the findings, and prints a structured summary inline with the halt (Lesson 13: audit beats observe). Pass this flag to suppress that extra claude call -- useful in CI runs that prefer a minimal stderr footprint, or when you'll inspect drift manually via `git diff` and `plan-tool run --mode reconcile`. |
| `--no-triage` | on | skip the impact-weighted triage gate on findings. Default: when a finding carries impact/complexity tags (the plan-audit prompt's trailing ``(impact=…, complexity=…)`` on conceptual findings; the reconcile prompt's ``Impact:`` / ``Complexity:`` fields), the iteration loop skips applies whose complexity strictly exceeds their impact (low+medium, low+high, medium+high) -- those findings are reported on stderr and dropped from the open-set so convergence short-circuits when only triaged findings remain. Findings without triage tags (deterministic checks, untagged output) default to apply. Pass this flag to force-apply every finding regardless of triage tags -- useful for completeness sweeps where you want to land every applicable edit. |
| `--purity`, `--no-purity` | off | run the optional per-step MIXED-STEP purity Claude battery in phase 1. Default: OFF. Returned medium ``granularity-split`` hints remain advisory, while a scan that fails or is skipped after the battery budget expires is a blocking coverage gap. The ``PLAN_TOOL_PURITY_CLAUDE_TIMEOUT`` and ``PLAN_TOOL_PURITY_SCAN_BUDGET`` environment settings bound each call and the full battery. Off keeps the fast deterministic checks and conceptual audit passes. ``--no-purity`` remains accepted and is now a no-op. |
| `--include-info` | off | apply info-severity findings too. Default: info findings are advisory (a concept too vague to audit, a heuristic hit, a detail-only path) and are excluded from the apply loop -- they're still reported in the deferred summary, just not auto-applied. Pass this to spend claude tokens applying them as well. |
| `--no-collision-sidecar` | on | skip the change-collision sidecar pause when drift fires during apply_finding. Default: when drift is detected post-apply, plan-tool saves claude's edits to `<stem>-change-collision<ext>` next to each modified original, restores originals to pre-apply state, and pauses interactively for the user to merge with their preferred tool (vimdiff, `code --diff`, meld, etc.). Pressing Enter at the prompt continues the iteration loop against the merged state; Ctrl-D / typing 'abort' halts as today. Pass this flag to revert to the legacy 'keep claude's edits on disk, review via git diff' behavior -- useful when scripting or piping to a CI consumer that doesn't expect sidecar files. Headless runs (-y or non-TTY) auto-skip the pause and fall through to halt regardless of this flag, since there's no human to merge. |
| `--fail-on-findings` | off | exit non-zero when the audit's blocking findings are present (completeness: stage-bar-aware blocking, incomplete audit samples, or ineligible iterate stop; verify-all: a [FAIL] / critical finding; validate: INVALID). Off by default; intended for CI gates that stop the pipeline on findings. |
| `--iterate`, `--no-iterate` | off | after the audit, run the same apply-findings / re-audit convergence loop the other subcommands use (shared ConvergenceState + iteration lock + scope guard): apply each eligible deterministic well-formedness finding via claude and re-audit until findings converge (conceptual findings require the human or orchestrating session to read and hand-edit the relevant plan or detail files) or --max-iterations / --iteration-budget is hit. Before the first apply this saves a pre-apply checkpoint report under the usual <ts>-completeness names, marked in its payload as crash-recovery evidence so it is skipped by --reuse-audit and by convergence history; the run's final report is written after the loop and is the eligible one. Default off -- pass --iterate to opt in or --no-iterate to assert it stays off. |
| `--json` | off | emit machine-readable JSON instead of the grouped markdown report. Top-level keys include stage (bare\|detail), audit_incomplete, conceptual_bar_blocking_ids (null when incomplete), and bar-aware has_blocking_findings (not flat medium+ on conceptual findings). The payload includes a top-level coverage block (budget_limited, optionally early_stop_reason for a terminal plan quota, passes_used, cap, conforming_pass_count, failed_or_malformed_pass_count, recommendation_kind, recommended_passes, recommendation_advice, confirmation_kind) so machine consumers can distinguish a clean audit from pass-cap and terminal-plan-quota coverage-unconfirmed stops. A terminal plan quota ends conceptual sampling for that invocation, reports early_stop_reason: plan-quota, and writes no ordinary final reusable findings sidecar. The three recommendation fields are retained as null compatibility keys; a fresh run-grade arm-clustering result appears separately as audit_shape_advisory with non-routing keep-or-carve evidence. |
| `--audit-passes` `N` | — | how many full, independent conceptual-audit passes to run, unioning findings by stable id so one report captures the stable set rather than a single pass's subset (default: 3). Each pass is a complete audit over the whole plan + code at HEAD — extra passes re-roll the LLM's non-determinism, they do not cover more of the plan, so the count is static, not scaled by plan size. 1 reproduces the legacy single-call behavior; higher trades claude calls for coverage. Passing this explicitly forces a fresh audit even when a reusable saved audit exists (unless --reuse-audit is set). |
| `--audit-samples` `N` | — | (deprecated alias of --audit-passes) |
| `--reuse-audit`, `--no-reuse-audit` | — | reuse the saved conceptual audit's findings instead of re-running the claude call, when the saved audit is fresh (plan AND code fingerprints still match). Default (unset): prompt interactively, auto-accepting under --yes / --json / non-TTY stdin. --reuse-audit always reuses a fresh save (even over an explicit --audit-passes); --no-reuse-audit always re-audits. A stale save is never reused — it declines to a fresh audit with a staleness note. Only an ordinary final sidecar is eligible: the newest save is skipped when its payload marks it a pre-apply checkpoint, carries an unrecognized role, or is not a completeness payload despite the filename, and the next eligible final is used instead. |
| `--reuse-audit-id` `STEM` | — | pin reuse to a specific saved completeness audit by filename stem (the bare `<ts>` or full `<ts>-completeness` form); default: newest eligible `-completeness.json` for this plan. This stays an exact selection request: an id naming a pre-apply checkpoint, an unrecognized role, or a non-completeness payload supplies no reusable findings and never silently falls back to an older report. An unresolved or ineligible id prints a note and runs a fresh audit; no sidecar needs renaming. |
| `--audit-dry-rounds` `N` | `1` | stop early after N consecutive audit passes surface no new finding (default: 1); capped by --audit-passes. The default 1 stops on the first no-new pass; raise it to require a streak of confirming dry passes (treating a single dry pass as noise) at the cost of extra Claude calls. Cost scales with how long the plan keeps discovering, bounded by the --audit-passes hard cap. |
| `--commit` | off | after a clean --iterate run that applied findings, stage all changes (git add -A) and create one commit with subject 'plan(<slug>): completeness — applied audit findings'. Requires --iterate (an audit-only run makes no plan edits) and a clean working tree up front; off by default; ignored with --json. |
