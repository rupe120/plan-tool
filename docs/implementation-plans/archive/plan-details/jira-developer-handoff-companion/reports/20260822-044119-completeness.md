- HIGH `[generated-target-detail-protection]`: Step 5 (`Publish synchronized story and handoff source files without overwriting human guidance`) narrows Architecture’s “any generated target equal to the plan source or a detail artifact from either grade” to “either target equal to the plan source or a selected detail artifact.” With `--grade jira`, an explicit story output can equal a run-grade detail file that is neither selected nor in the Jira authoring lane; this misses the Testing and Acceptance criteria requirement to reject “any detail artifact” and can overwrite human guidance.
  - Fix: Reject either generated target when it equals any run- or Jira-grade detail artifact, including the unselected grade, and test that path before invocation or staging.
- HIGH `[dropped-story-id-collision]`: Architecture, Testing, and acceptance criterion 5 retain dropped records as unchanged story-source history, but step 3 (`Regenerate companion-mode stories with provable Jira-key ownership and state`) does not reserve those IDs before parsing new stories. At HEAD, `plan_tool.jira:compute_start_number` excludes the current output and `parse_jira_response` only rejects supplied `known_ids`, so a regenerated story can reuse a retained dropped record’s `<EPIC>-S<N>` and produce two conflicting story identities.
  - Fix: Reserve every retained historical story ID while validating regenerated stories and test that an ID collision refuses publication.
- HIGH `[created-ticket-lifecycle-notice]`: Architecture reclassifies a record covering only parked or removed work as dropped history even when it has a Jira key, but step 3 returns update metadata only when a created record is “reattached to regenerated story content,” and step 6 (`Add an opt-in Jira companion CLI mode with explicit output behavior`) reports only changed regenerated stories. A keyed created ticket that leaves committed coverage receives no manual cancel-or-repurpose notice; `plan_tool.jira:_export_jira_append` and `plan_tool.cli.jira_cmd:_print_jira_followups` already surface this exact lifecycle transition as `dropped_in_jira`.
  - Fix: Carry keyed created-to-dropped transitions through the companion result and CLI as a distinct manual Jira follow-up, with lifecycle tests for parked and removed coverage.
