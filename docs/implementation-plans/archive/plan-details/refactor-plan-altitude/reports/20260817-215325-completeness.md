  - Fix: preserve the opt-out explicitly and scope the final Architecture-refresh guarantee to synthesis-enabled runs, with a test for the no-synthesis path.

The Architecture eligibility rule, Testing unclassified case, and Acceptance eligibility criterion leave opposite eligibility results possible for the same committed `change_type: null` step.
  - Fix: make eligibility a closed rule: only explicit `refactor` code steps and explicit `non-code` companions may qualify, while every committed unclassified step is ineligible.
- HIGH `[final-architecture-failure]`: Step 2’s Architecture, Risks, Testing, and eligible-Architecture acceptance criterion require the final map to reflect the surviving graph, but define no result when final synthesis is malformed, all-null, or returns no Architecture. At HEAD, `plan_tool/create.py:propose_body_sections` returns an all-null result after its retry and `_prepare_create_plan` treats it as a skip, so finalization can leave Architecture for an earlier graph.
  - Fix: define and test the terminal failure policy that prevents an eligible final graph from retaining stale Architecture or silently succeeding without it
- HIGH `[eligibility-transition]`: The Overview requires Architecture to never describe “a provisional proposal or an earlier graph,” and Step 2 says finalization runs again after each graph replacement, but the same paragraph says “Feature, mixed, ineligible, and direct-canonical graphs retain the existing Architecture behavior.” An eligible graph followed by an ineligible convergence graph has no stated action to remove or restore the earlier outer-boundary map.
  - Fix: define and test the eligible-to-ineligible transition so the final Architecture always matches the surviving graph or the preserved pre-policy behavior
