Step 2's Input quotes the rule as `(?<![A-Za-z0-9_.-])name(?![A-Za-z0-9_.-])`. A bare name that ends a sentence, as in "Derived from 04-roadmap.md.", is therefore not an occurrence, so the body check never sees it. The same goes for a name followed by `-` or `_`. The plan promises the opposite, in step 2: `"It is a plain presence check that never judges citation versus mention."` The Architecture section says the check "rejects every bare occurrence". The Acceptance criteria say `"no roadmap file name that a plan carries from a draft seed passing the gates names a top-level `01-domain.md` … `04-roadmap.md`, in any section, fenced code included."` A seed can pass the gates with a sentence-final bare name in Architecture or Risks. `create` then copies that name into the plan, which is the stale-copy citation this work exists to stop. The rule is only safe in the References gate as it stands, because that gate asks "is the name present", not "is every bare name rejected". The same trailing-character rule means a correct version-store path that ends a sentence would not count toward the References requirement. Step 2's tests list no sentence-final or trailing-punctuation case. Sites: step 2 Implementation (shared occurrence rule) and Tests, the Architecture "Draft-seed gates" bullets, the Acceptance criteria, and step 3, which calls the same function on promoted copies.
  - Fix: State in the plan and step 2 that the body check uses its own occurrence rule: a member filename is a violation unless a longer filename contains it, and trailing sentence punctuation such as `.` does not hide it. Add sentence-final and fenced-final cases to the step 2 tests, and apply the same rule to the References gate's path match.
