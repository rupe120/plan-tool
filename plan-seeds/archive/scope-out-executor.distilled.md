## Overview

Adds `plan-tool scope-out <plan> --step N`, the actuating half of the structural-remedy work carved out of `structural-remedy-vocabulary` (whose advisory arms — the convergence scope-out recommendation, the reconcile finding, the docs — land first). When a region of a plan is spinning (recurs + no-shrinkage at `max_severity ≥ high` with a non-decreasing first→last severity trend — the "patches backfire" signature `convergence` detects), scope-out carves that region out so the rest converges. It performs two mutations **seed-first**: emit a `create --from-existing` forward-seed for the carved step under `plan-seeds/<plan>-carved-<slug>.md`, then narrow the plan. The actuating path is opt-in flag + interactive confirm `yes`; every other path recommends only, spends no Claude, mutates nothing.

## Problem statement

Today the scope-out remedy exists only as prose: the convergence diagnostic recommends carving a spinning region but there is no runnable command to do it. The carve needs **new code + resolved design** rather than composing existing executors — its narrowing half has no precedent: no existing executor *drops* a step. `split_step` is one→many; `merge_steps` folds many→**one survivor** and repoints dependents to it (`create._apply_step_merge`). A deep audit of the combined plan put almost every HIGH/structural finding on this executor because it touches hard plan-graph mechanics (dependency edges, run cursor, detail-file lifecycle) and the run-state "carry" has a real mechanism subtlety. Without it, a spinning region keeps getting patched in place instead of carved out to somewhere durable and re-plannable.

## Architecture

**Seed-first atomicity contract.** A crash after the seed write leaves a harmless re-runnable orphan seed; a crash before it leaves the plan untouched.

**Run-state "carry" = done-context PROSE, not a live-status round-trip.** The carved step typically has run state (it is the spinning, often CURRENT step). But `create --from-existing` re-decomposes into fresh PENDING steps and cannot round-trip live `status`, and `schema.Step` has **no `progress` field** (only `status: StepStatus` and the ephemeral `status_note`). So the seed carries the carved work as done-context prose — what was implemented, what remains, and the carved step's `status`/`status_note` rendered as narrative — exactly as `annotate_render.render_create_seed`'s done-context block does for the whole-plan path. The re-plan *accounts for* that context; it does not resume an in-progress step verbatim. Do **not** reuse the PENDING-only safety gate verbatim (`merge_steps`/`split_step`/`escalate_to_split` refuse a run-started target) — that would forbid the exact case scope-out exists for. (fixes `progress-source-undefined`, `runstate-resume-overclaim`)

**The narrow is a NEW primitive with its OWN drop-renumber — not a reuse of `merge`.** `_apply_step_merge`'s renumber is private inline fold-logic (collapses members onto a survivor), not a callable unit and not shaped for a drop (which has no survivor). The narrow writes its **own** small drop-renumber: shift survivors after the hole down by one and rebuild the `depends_on` edges. Reuse only the detail-file migration helper (`detail._migrate_downstream_details_after_merge` renames downstream files to their new ids); do not claim reuse of merge's renumber, and do not fold an extract-shared-helper refactor into this step (that would make it a refactor+feature mixed step). (fixes `narrow-drop-primitive`, `narrow-renumber-reuse-feasibility`)

**Dependency-graph integrity across the drop (the central correctness gap).** The carved step has edges in both directions and both must be handled explicitly — a silent id reuse corrupts the graph with no validation crash. **Inbound** (a surviving step `depends_on` the carved step): after drop+renumber that id is reused by a different step. `_apply_step_merge` repoints dependents to the survivor; scope-out has **no survivor to repoint to**, so it must **refuse** (recommend-only) when a surviving step depends on the carved step — unless the whole dependent sub-tree is carved together (Deferred). **Outbound** (the carved step `depends_on` surviving upstream steps): those prerequisites must be captured in the seed as done-context so `create --from-existing` re-establishes the assumption. (fixes `carved-step-dependents`, `carved-step-upstream-deps`)

**Carved step's own detail file → archive.** The narrow migrates downstream detail files (`id > survivor`); the carved step's own detail file would be left orphaned. Archive it (mirror `merge_steps`, which archives folded-away files), since its body is already captured in the seed. (fixes `carved-detail-file-disposition`)

**Re-establish a run cursor in the narrowed plan.** After dropping a run-started (typically CURRENT) step, a plan left with a DONE+PENDING mix and no CURRENT has no cursor for `run` to resume from (`create._seed_initial_step_status` only promotes a CURRENT when all steps are PENDING). The narrow must promote the appropriate survivor (the first PENDING after the last DONE) to CURRENT. (fixes `narrowed-plan-current-pointer`)

**Intra-narrow atomicity + the safety gate (mirror `escalate_to_split`).** The narrow is multi-step (drop + renumber + repoint depends_on + migrate/archive detail files + set cursor); compute the full new-plan + file-op plan in memory (a dry-run preview, as `merge_steps(dry_run=True)` does), validate, then apply all-or-nothing with rollback — never a partial on-disk state. The mutation applies only when **safe** (no inbound dependent on the carved step; no downstream non-PENDING step orphaned by renumber) **+ opt-in flag + interactive confirm `yes`**; every other path (unattended, unsafe, non-TTY, declined, empty-plan) recommends only, spends no Claude, mutates nothing. Return a frozen `EscalateResult`-style value (`outcome` ∈ `applied` / `recommended` / `unsafe` / `step-missing` / `empty-plan`; only `applied` mutates); re-parse the plan from disk on entry. (fixes `narrow-atomicity`)

**Empty-plan guard.** Carving the plan's only surviving step would produce a `steps: []` plan — the rot the forward-seed disposition exists to avoid. Refuse (outcome `empty-plan`) with a message pointing at a full re-seed (`create --from-existing`). (fixes `scope-out-last-step-empty-plan`)

**Carved-region seed emitter — adapt, don't force-reuse.** `annotate_render.render_create_seed(annotation: PlanAnnotation, *, report_path)` consumes a whole-plan `PlanAnnotation` (from `annotate.classify_plan_implementation`, a Claude pass) and writes beside the source — wrong contract for a carved single-step subset under `plan-seeds/`. Build a focused, deterministic carved-region renderer (no Claude) that serializes the carved `Step` + its detail body + the done-context prose + the captured upstream-dep context. (fixes `scope-out-seed-emission-reuse`)

**Dependency on the advisory plan (single-step only).** This plan depends on `structural-remedy-vocabulary` landing first and flips its scope-out recommendation from prose-only to a runnable command — but only for the single-step case. `plan-tool scope-out --step N` needs one resolved step id; `classify_fork` sets `step=None` on `FORK_STRUCTURAL` / unresolvable foci, so `render_diagnosis` renders the runnable `--step N` command only when a single step resolves and falls back to prose-only otherwise — never emitting a `--step` line with no id. (fixes `scope-out-arm-step-focus`)

**New surfaces.** Orchestrator in a new `plan_tool/scope_out.py` leaf; thin `plan_tool/cli/scope_out_cmd.py` handler wired into `app.py` (dispatch) + `parser.py` (argparse). Seams reused/extended at HEAD: `plan_tool/detail.py` (`merge_steps`/`split_step` gating + dry-run + canonical-numbering model, `_migrate_downstream_details_after_merge`, `MergeResult`, archive behavior); `plan_tool/create.py` (`_apply_step_merge`, `_seed_initial_step_status`); `plan_tool/annotate_render.py:render_create_seed` + `plan_tool/annotate.py` (`PlanAnnotation`, `classify_plan_implementation`, done-context block); `plan_tool/launcher.py` (`escalate_to_split` + `EscalateResult`); `plan_tool/convergence_diagnosis.py` (`render_diagnosis`, `classify_fork`, `_split_command`, `_reseed_command`); `plan_tool/schema.py` (`Plan`/`Step`/`StepStatus`/`status_note`).

## Out of scope

- A new split/merge algorithm for the **step** altitude — reuse `split_step` / `merge_steps`.
- **Multi-step / multi-region carve** — Deferred; this executor is single-step (`--step N`); the recommendation falls back to prose for the multi-region case.
- **Auto-mutating structure unattended** — every actuating path stays opt-in + interactive-confirm; default recommends only, spends no Claude.
- A **BACKLOG.md writer** or an **in-plan `DEFERRED`** disposition — the carved part is a forward-seed (settled in the vocabulary plan).
- The **advisory arms themselves** — those ship in `structural-remedy-vocabulary`.

## Risks

- **Silent graph corruption** — a dropped step's id is reused by renumber with no validation crash. Mitigation: the inbound-dependent refusal + explicit `depends_on` repair (decision 3); test a surviving step depending on the carved step.
- **Run-state overclaim** — carrying live status would falsely claim a resumable in-progress step. Mitigation: carry as done-context prose, not a live-status round-trip (decision 1); the AC tests assert prose content + re-plan accounting, not a non-existent field.
- **Partial on-disk state** — a crash mid-narrow could leave inconsistent frontmatter/detail files. Mitigation: dry-run-preview-then-apply + rollback (decision 6) + seed-first ordering.
- **Lost run cursor** — the narrowed plan could have no CURRENT to resume from. Mitigation: re-establish CURRENT in the narrowed plan (decision 5).
- **Doc double-write** — this plan and the vocabulary plan both touch RUNBOOK/CLAUDE docs. Mitigation: sequence so a watched-file drift guard does not halt mid-run.

## Testing

Unit-first, mirroring `plan_tool/scope_out.py` → `tests/test_scope_out.py`. Cover: the deterministic carved-region seed emitter (serializes carved `Step` + detail body + done-context prose + captured upstream-dep context, spends no Claude); the narrow primitive's own drop-renumber, `depends_on` repair, detail-file migrate/archive, and CURRENT re-establishment; the safety gate's refusal paths. Specific scenarios the seed names: a surviving step depending on the carved step causes a refusal (recommend-only), never a silent id-reuse; the carved step's run state is asserted as done-context **prose content + re-plan accounting**, not a non-existent `progress` field; carving the only surviving step is refused with outcome `empty-plan`; the default / unattended / unsafe / non-TTY / declined paths recommend only, spend no Claude, mutate nothing (frozen `EscalateResult`-style value where only `applied` mutated); atomicity (dry-run preview + apply-or-rollback) leaves no partial frontmatter/detail-file state on crash. Cover the convergence render flip in `convergence_diagnosis` tests: `render_diagnosis` emits the runnable `plan-tool scope-out … --step N` only when the localized fork resolves a single step, and prose-only otherwise. Add an `@pytest.mark.integration` test driving `plan-tool scope-out <plan> --step N` end-to-end (seed-first emission then narrow) only for the cross-module CLI wiring a unit test would miss.

## Acceptance criteria

- `plan-tool scope-out <plan> --step N` (opt-in + interactive confirm, on a safe plan) emits a `create --from-existing` forward-seed carrying the carved work as done-context prose (incl. its upstream-dep context), then narrows the plan — seed-first, never dropping the carved work.
- The carved step's run state is captured as done-context prose (status + status_note rendered as narrative) — not a claimed live-status round-trip, and not refused or silently discarded; an AC test asserts the prose content, not a non-existent `progress` field.
- The narrow repairs `depends_on`: a surviving step that depends on the carved step causes a refusal (recommend-only), never a silent id-reuse; the carved step's own detail file is archived; a CURRENT cursor is re-established.
- The narrow is atomic (dry-run preview + apply-or-rollback); no partial frontmatter/detail-file state on crash.
- Carving the plan's only surviving step is refused (`empty-plan`) with a re-seed hint; the default / unattended / unsafe / non-TTY / declined paths recommend only, spend no Claude, and mutate nothing — a frozen `EscalateResult`-style value where only `applied` mutated.
- `plan-tool convergence` renders the runnable `plan-tool scope-out … --step N` only when the localized fork resolves a single step, and prose-only otherwise (multi-region) — never a `--step` line with no resolvable id.

## Deferred

- **Multi-step / multi-region carve** — this executor is single-step (`--step N`); when the localized fork holds a multi-region focus (`classify_fork` sets `step=None`), the recommendation falls back to prose-only. Deferred because resolving a multi-region carve (e.g. carving a whole dependent sub-tree together) requires handling inbound dependents that are themselves carved, beyond this plan's single-step scope.
