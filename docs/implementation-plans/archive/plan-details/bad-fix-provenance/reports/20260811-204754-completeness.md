- HIGH `[intervening-remedy-ordering]`: Step 5 (`Add the bad-fix provenance advisory to convergence`) treats a report’s `created_at` as the real recurrence time, but `plan_tool/completeness_report.py:_reserve_report_timestamp` can advance colliding reports into future whole seconds and `write_completeness_report` persists that reserved value as `created_at`. A remedy recorded after the real recurrence can then appear earlier than its stored time and trigger a false bad-fix advisory.
  - Fix: Define one truthful, sufficiently precise report-event order for every bad-fix before/after check, separate from collision-reserved report naming or identity time.
- MEDIUM `[same-issue-identity]`: Step 5 (`Add the bad-fix provenance advisory to convergence`) falls through from unusable body skeletons to Step 4’s unchanged title fallback without requiring usable titles. At HEAD, `plan_tool/convergence_diagnosis.py:_title_ratio("", "")` is `1.0`, so empty or punctuation-only titles can match and turn an unrelated qualifying note into an advisory.
  - Fix: Require non-empty normalized titles on both sides before Step 5 uses the title fallback, while leaving Step 4’s shared helper unchanged for existing `_matches` consumers.
- MEDIUM `[collapsed-source-finding]`: Steps 2 (`Persist qualified remedy provenance on annotations`) and 5 (`Add the bad-fix provenance advisory to convergence`) retain an event’s recommendation id and `Annotation`, then match through `CompatiblePass.findings`; at HEAD, `build_collapsed_completeness_passes` replaces those findings with the newest collapsed snapshot. A later recurrence can therefore be compared with a changed re-audit finding rather than the finding that received the remedy note.
  - Fix: retain the original finding identity data with every source annotation event and match the recurrence against that source finding before selecting evidence across all collapsed events
- MEDIUM `[annotation-event-history]`: Step 2 (`Persist qualified remedy provenance on annotations`) calls every new write an event, but `plan_tool/review_persistence.py:update_annotation` replaces `annotations[rec_id]`. A rewalk or later hand record can erase a qualifying applied remedy before collapse sees it, despite the plan requiring every source annotation event to survive.
  - Fix: Preserve repeat dispositions as ordered events inside the existing annotation persistence contract for every writer and collapse consumer.
- MEDIUM `[remedy-event-order]`: Step 2 defines `recorded_at` as valid UTC and Step 5 selects the latest event, but `plan_tool/review_persistence.py:_utc_now_iso` currently has whole-second precision and the plan defines no tie rule. Multiple accepted remedies in one second have no deterministic most-recent note.
  - Fix: Define a total ordering for remedy events, including tied timestamps, and apply it consistently to all writers, collapse selection, rendering, and tests.
