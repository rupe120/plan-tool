The Overview and the stated intent promise that a reviewer sees the findings "before approval". The plan does not say whether a missing or stale record found inside `seal_review` or `decide_structural_candidate` approve is regenerated and then approved in the same invocation. Reconcile steps 1, 4, 6, and 7 to this rule.

Step 5 adds a prompt and a call that touch the same candidate modules. If step 1 runs first, it fixes the outcome vocabulary before the correction operation exists.
  - Fix: Apply the IPPT-18-landed precondition and its stop-and-surface rule to step 1, which defines the outcome vocabulary, as well as steps 2 and 3. Make step 1's vocabulary refer to the correction operation as IPPT-18 defines it.
- MEDIUM `[blocking-defect-exit-path]` [confidence: limited]: Step 1 selects which deterministic defects block approval. The plan names an exit path for each closed-vocabulary state, but it gives no way for a reviewer to clear a blocking removed-id finding that they judge a false positive, for example a reference that is neither historical nor an actual reuse. That conflicts with the Testing case "ambiguous references" and with the fence that no refusal is keyed on meaning.
  - Fix: Have step 1 define, for each blocking defect class, the operator's exit: a correction operation or a structural historical marker. State that an ambiguous reference is a non-blocking evidence item and not a blocking defect.
