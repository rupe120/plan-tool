- HIGH `[namespace-directory-lifecycle]`: Step 1 (`Add minimal immutable evidence publication and enumeration helper`) leaves the `ESCALATIONS` namespace-directory lifecycle unchosen: Architecture says the helper “derives the namespace directory” but defines only the final-directory fsync. A root-level namespace, a required pre-created child, and a first-use child all comply, but a newly created child also needs its parent-directory durability boundary before `created`; otherwise the Overview’s first-writer durability, the host-failure Risk, Testing’s valid-winner case, and acceptance criteria 2–3 can fail. [fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html)
  - Fix: Define the `ESCALATIONS` directory location and first-use policy, including every directory durability boundary required before `created`, and cover that policy in the criteria and tests.
- MEDIUM `[temporary-cleanup-ownership]`: Step 1 allows a later call to remove a crash-left dot temporary, while Architecture, the Reduced-scope fence’s “exclusive create resolves the only real race,” the crash-temporary Risk, Testing’s cleanup case, and acceptance criterion 4 require competing creators to reach `existing`. A later call can unlink a live publisher’s source temporary before its link, making that publisher return `write-failed` instead; without an ownership rule, cleanup can also delete an unrelated dot-prefixed entry that scans are otherwise required to ignore.
  - Fix: Restrict cleanup to the current call’s own temporary and make cross-call crash leftovers ignore-only, then align the cleanup, contention, and unrelated-entry tests with that rule.
- MEDIUM `[enumeration-invalid-input]`: Architecture says a wrong namespace returns `invalid-input` before storage opens, but its closed enumeration contract says enumeration returns only records or `write-failed`. Step 1, Testing’s sealed-registry check, and acceptance criterion 1 leave an invalid namespace passed to enumeration without one defined observable result.
  - Fix: state enumeration’s invalid-namespace outcome explicitly and align the validation, result-contract, test, and acceptance language.
- HIGH `[existing-record-durability]`: Step 1 (`Add minimal immutable evidence publication and enumeration helper`) can return an `existing` record, or enumerate a linked final, before the winning publisher performs the final-directory `fsync`: Architecture syncs that directory only on the `created` path, while the `EEXIST` path rereads immediately and scans expose matching finals. Risks, Testing, and acceptance criteria 2–5 protect only `created`, so a caller can act on opaque bytes that disappear after a host failure.
  - Fix: require every path that returns an already linked final, including race losers and enumeration, to establish the necessary directory durability or return `write-failed`, and test the ordering
- MEDIUM `[temporary-name-exclusivity]`: Step 1 calls for a “primitive-named” dot temporary but never requires unique, exclusive temporary creation. Architecture’s same-directory write/link sequence, Testing’s competing-creator case, and acceptance criteria 2 and 4 allow two live publishers to select one temporary pathname and overwrite or unlink each other’s staged bytes before exclusive final linking decides the winner.
  - Fix: require per-call exclusive temporary creation with a non-final dot name and add an interleaving case that proves colliding publishers cannot share staged bytes
