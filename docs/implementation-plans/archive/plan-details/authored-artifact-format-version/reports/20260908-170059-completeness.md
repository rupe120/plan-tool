- MEDIUM `[authored-version-support-window]` [confidence: limited]: The support window and retirement rule step 5 writes into `DATA_CONTRACT.md` leaves two states undefined, and step 2's serializer rule makes the second one concrete. The policy the plan commits to is:

```
An additive field or section with a default does not bump a
version. A break does. Readers support current and current-minus-one; writers
emit current only; version N retires by a dated, user-approved record before
N+2 ships.
```

```
Both serializers inject the current declaration into their serialized mapping
after the model dump, including the concept-sync publish path; the written

```

  First, `absent` maps to version 1 at both gates and the step 6 coverage test enumerates `absent` permanently, yet the retirement rule lets version 1 retire — the policy never says whether `absent` retires with it, which would make every never-rewritten plan and detail file unreadable, or is pinned as permanently supported. The policy never says whether a rewrite preserves a declared version or replaces it. Neither gap needs version 2 to exist; both are holes in the rule text step 5 ships.
  - Fix: State in the authored-artifact version-evolution policy whether `absent` retires alongside version 1 or stays permanently supported, and whether a serializer rewriting a supported older-version artifact preserves that artifact's declared version or must route through the explicit upgrade entry point.
