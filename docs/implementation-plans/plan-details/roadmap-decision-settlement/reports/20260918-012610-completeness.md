Step 7's acceptance ("prove... `check_settled_decisions` still refuses drift on a row this route settled") cannot be demonstrated against the real enrolled pipeline this way — it can only be shown by calling the gate directly on a hand-built envelope, which proves nothing about whether a real subsequent promotion is actually blocked.
  - Fix: For the enrolled lineage, either add a dedicated drift check to the candidate-promotion validity path that compares a proposed candidate's decisions against the currently accepted version's settled decisions (the same comparison `check_settled_decisions` already makes, given a real predecessor), or state plainly in Risks/Deferred that a settled decision on an enrolled roadmap has no protection against a later candidate promotion until a separate effort adds it — rather than leaving the References/Out-of-scope framing assert a protection this lineage does not have.
