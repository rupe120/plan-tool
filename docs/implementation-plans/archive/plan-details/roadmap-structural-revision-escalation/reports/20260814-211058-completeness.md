  - Fix: Define receipt storage as a non-link directory containing only regular receipt files, and classify link or special entries as invalid without following them for creation, reuse, or views.
- MEDIUM `[receipt-schema-closedness]`: Overview and Architecture say version-1 receipts record only a redacted field set, but step 3’s schema, step 4’s reuse validation, step 5’s views, Testing, and acceptance criteria 3 through 5 never say that unknown fields make a receipt invalid. A version-1 file can add `feedback_request` or target prose while retaining a valid semantic id because the preimage covers only recorded fields, leaving reuse and display open to accepting forbidden content.
  - Fix: Make the version-1 field set closed before identity validation or reuse, and limit invalid-evidence views to safe status and location metadata.
- HIGH `[receipt-reuse-durability]`: Step 4 (`Durably publish receipts with redacted escalation lifecycle evidence`) promises reuse only after file and parent-directory durability, but Architecture lets a loser re-read and emit `reused` immediately after the winner’s exclusive link. The host-failure Risk, Testing’s file-publication paragraph, and acceptance criterion 3 leave a window where the loser reports reusable evidence before either creator fsyncs the receipt directory.
  - Fix: require a reuser to establish or observe the final receipt’s file-and-directory durability before emitting `reused`, and test that interleaving
- MEDIUM `[escalation-view-conflicts]`: Step 5 (`Wire exclusive escalation creation and log-free receipt views`) defines rejection for creation flags beside “an escalation view,” but `plan_tool.cli.roadmap_cmd:register` already offers `--view summary`, `walk`, `ledger`, `index`, and `seeds`. Architecture’s mode matrix, Testing’s paired-option coverage, and acceptance criterion 2 do not say what a complete creation pair beside one of those views does, so it can be ignored or reach the old view dispatcher.
  - Fix: State that either creation flag conflicts with every `--view` value and is rejected before any view or broad-mode dispatch.
