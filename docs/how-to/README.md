# How-to guides

*Task-oriented plan-tool documentation. Start at the [README](../../README.md).*

Use these routes when you know what you want to do. They point to the existing
step-by-step workflow or recovery guide; they do not repeat every option or
the rationale behind a rule.

Keep reusable procedures here: prerequisites, ordered actions, expected results
and recovery paths. Put session status, unfinished updates and owner questions in
[handoffs](../../handoffs/README.md); use [evidence](../evidence/README.md) for
measured outcomes and [explanations](../explanations/README.md) for rationale.

For source installation, version selection and dependency/skill refresh, use
[Install and update](install-and-update.md).

## Author and run a plan

1. Choose a starting input in [Choose a starting point](choose-a-starting-point.md).
2. Follow the normal commands in [Your first plan](../../README.md#your-first-plan).
3. Use [Common workflows](common-workflows.md) when a stage needs its options or
   exception path.

For a project-sized concept, start with
[roadmap](common-workflows.md#0-roadmap--stage-a-project-sized-concept-optional).

## Recover or operate a run

- Use the [Runbook](../../RUNBOOK.md) for a failed, stalled, or surprising
  command result.
- Use [Operations](../OPERATIONS.md) for headless runs, checkpoints, logs,
  and worktrees.
- Use [Commands](../reference/commands.md) for a short command reminder, then the
  generated [CLI reference](../cli/README.md) for every option.
