  - Fix: State one rule for the detail-file part of the footprint across steps 2, 3 and 5. - MEDIUM `[commit-pathspec-empty-entry]` [confidence: limited]: Step 1 commits with `git commit -m <subject> -- <pathspecs>` and says "An entry with no change is staged harmlessly." That holds for `git add -A -- <path>`, but `git commit -- <pathspec>` fails with "pathspec did not match any file(s) known to git" when an entry matches nothing tracked or staged. An existing but empty `plan-details/<slug>/` directory is such an entry, as is a directory holding only gitignored files. Both are plausible, because steps 2–5 always pass the plan's details directory. Step 1 skips entries that are absent and untracked or gitignored, and makes a footprint with no changes a no-op. It does not cover a footprint where some entries have changes and another matches nothing git knows. In that case the whole commit would fail even though the verb succeeded. Its test list has no such case.
  - Fix: Have step 1 decide, before committing, which footprint entries git knows about (tracked, or newly staged by the add). Commit only those, so an entry that matches nothing is skipped like an absent one. Add a test with an empty directory entry next to a changed entry.
