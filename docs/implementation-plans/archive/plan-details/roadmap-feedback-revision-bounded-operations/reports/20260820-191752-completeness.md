Unsound or contradictory concepts in the plan's design — the highest-priority gaps, addressed before the completeness gaps below. The audit reports these but does not apply them (read-only-audit split, #85): the paired apply verb walks them first, before the completeness gaps. Address them with:

- HIGH `[stage-source-admission-race]`: Step 5 (`Route every re-entered stage by active feedback, refuse unauthorized non-feedback changes, and re-gate feedback-free stages without writes`) rechecks a normal binding only before “a later stage” uses it or before candidate publication. A direct semantic edit can therefore land after admission but before a terminal feedback-free stage’s own re-gate; the stale in-memory artifact can pass and return `OUTCOME_COMPLETED_NO_CHANGE` instead of `OUTCOME_STAGE_INVALID`, contrary to the Architecture source-admission guarantee.
  - Fix: Recheck every normal-route file binding immediately before every gate or route use, including each feedback-free re-gate, and cover concurrent edits on no-op paths.
- MEDIUM `[removal-relation-scope]`: `remove-row-with-record` promises to reject when “any surviving declared relation” names the row, but step 2 says “Context may use the current stage and its earlier artifacts, never downstream stage content,” and step 5 retains an earlier merge when a later feedback-free re-gate fails. A Domain, Constraints, or Components removal can therefore publish before an existing downstream relation is checked.
  - Fix: Narrow the removal rule to current-and-upstream relations and state that downstream breakage is detected by the later re-gate, matching the selected context boundary.
- MEDIUM `[feedback-snapshot-retry-boundary]`: Step 5 promises that changed feedback refuses “without a write, retry, correction request,” but its snapshot check runs only “before every bounded stage candidate publishes” while parse, merge, and gate failures use the existing correction channel. A reviewer edit after a failed attempt can therefore cause a stale correction prompt and retry before publication detects it.
  - Fix: Define feedback-snapshot checks before every correction or retry as well as before publication, and cover a change between attempts.
- CRITICAL `[publication-check-write-race]`: The concurrent-change guarantee is not achievable with the stated final checks: Architecture says a reviewer change is “never lost,” but step 4’s “final guarded callback” and step 5’s pre-write rereads still run before `atomic_write_text`; at HEAD, `roadmap_revision_publish.roadmap_writer_guard` is advisory and `publish_revision_candidate` calls `before_replace()` before replacement. An uncoordinated raw feedback or semantic edit can land in that interval and be overwritten.
  - Fix: define a publication protocol that prevents an uncoordinated artifact edit from being replaced after the final source and feedback check, then align the no-loss promise, documentation, and tests to that guarantee.
