The plan does not say how those counters compose, so retries can be mislabeled or indistinguishable within one plan phase.

A refresh with an earlier successful row and a later row-level refusal has no defined aggregate outcome because `partial` requires an exhausted row; separately, `plan_tool/shell.py:claude_invoke` converts runner exceptions into nonzero results that `plan_tool/roadmap.py:materialize_plan_seed` retries as invocation failures, despite Architecture requiring every unexpected phase exception to end as `error`.
  - Fix: define command-preflight, row-level refusal, and normalized backend-fault precedence, continuation, aggregate outcome, and exit behavior for selected and mixed batches.
