  - Fix: Align Store removal authority, continuity validation, and end-to-end coverage—either support it as a continuity case or reject it in the envelope.
- HIGH `[local-upstream-source-admission]`: Step 5 admits the selected local artifact before selector preflight, but not the upstream artifacts its publication gate consumes. At HEAD, `roadmap_revision_publish:publish_revision_candidate` reads every earlier stage directly, so a gate-clean semantic hand edit upstream can let `run_local_feedback_revision` publish against untrusted source, contrary to the Architecture’s before-upstream-gate rule and the Risks’ whole-projection local admission.
  - Fix: Require the local route to baseline-admit every artifact supplied to its publication gate and prove upstream semantic drift stops before invocation or publication.
- MEDIUM `[same-envelope-relation-targets]`: Step 1 says “New assumptions and decisions may point only to live predecessor rows,” while Step 2 says context must “reject a new same-envelope relation target.” The Architecture still admits relation-bearing added entities, rules, workflows, and components, so implementations can reasonably either reject or allow their references to another newly added row.
  - Fix: State one same-envelope reference policy for every relation-bearing add-row payload and align context binding and coverage to it.
- MEDIUM `[reentry-overwrite-guidance]`: Step 5 says “active feedback is the only re-entry path that calls the backend or publishes a change,” but `cli/roadmap_cmd.py:_overwrite_summary_lines` still says `--from-stage N` “rewrites every stage from N up.” Step 6 removes that promise from documents but not this runtime operator guidance, so a mixed merge/no-op run reports false overwrites and gives a bad preservation pointer.
  - Fix: Make runtime overwrite guidance distinguish actual writes from feedback-free re-gates and test mixed re-entry output.
