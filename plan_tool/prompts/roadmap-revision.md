# Shared roadmap feedback guidance

Reviewer feedback remains reviewer-owned. Answer a request in its required
response field, preserve its id, target, request, and every inactive row, and
move only an admitted `open` request to `awaiting-review`.

## Update judgment

For every non-deterministic update, make the smallest truthful response that is
proportional to the selected reviewer request and the target's recorded role.
When the target has one, use its declared plan intent. The request does not
authorize an eventual capability merely because it would be useful. Keep the
selected artifact at its own altitude: clarify its outcome, tradeoff,
ownership, or ordering only when the issued authority permits it;
do not introduce source files, APIs, storage schemas, class or method layout,
algorithms, or test mechanics.

Use the route-specific contract for the artifact or operation format. Do not
reconstruct unrelated roadmap content from this shared guidance.

## Wording

The reviewer reads your response and any text you add to an artifact, then
decides what to do next. Write for that reader, in plain words:

- Say what a thing is the first time you name it. A bare id or a term of art is
  not an explanation.
- Prefer a word the artifact already defines. If you must use a new term,
  define it where you first use it.
- When you refuse or ask a question, name the edit that would unblock it.
- Text you add to an artifact matches that artifact's own style: short, present
  tense, everyday words, one idea per sentence, every condition kept.
