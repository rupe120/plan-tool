# Design proposals

Keep proposed architecture and design alternatives here when a change needs
review before it becomes an implementation plan. State the intended outcome,
constraints, trade-offs and decisions the proposal asks a reviewer to make.

A proposal does not describe shipped behavior merely because it exists. Put
accepted operating contracts in [reference](../reference/README.md), durable
rationale in [explanations](../explanations/README.md), and ordered execution in
[implementation plans](../implementation-plans/README.md). Keep current session
status in [handoffs](../../handoffs/README.md). The `archive/` subtree retains
superseded proposals only when their decisions or provenance remain useful.
