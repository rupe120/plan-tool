  - Fix: change step 5 so a hand-resolution event from `telemetry.read_hand_resolved_ids` takes precedence whenever the paired run-reconcile snapshot doesn't itself confirm or redirect the same finding (not merely share a step number), and add a test for a step-anchored hand-resolved finding whose step later gets an unrelated run-reconcile — covering the general class, not just the two cited instances.
- MEDIUM `[hand-resolution-cleared-grouping]`: Architecture ("Where hand-resolution evidence actually goes") states the new path "groups the same way on `(finding_class, step, identity)`", but step 5's own scope description (the Authoritative scope input given above the plan body) says the opposite: the check is "independent of `step`/`identity`" and grouped "keyed on `(finding_class, origin.id)`". These are two different, mutually exclusive grouping keys for the same "keep only the latest occurrence before emitting one `cleared` observation" rule that the cleared-count-multiplicity test depends on.
  - Fix: pick one grouping key for step 5 — `(finding_class, origin.id)`, per the step's own more detailed description, since it needs no `step`/`identity` to resolve — and correct the Architecture section's prose to match instead of leaving the two descriptions to disagree.
- MEDIUM `[region-closure-ordering-claim]`: Architecture claims "`_region_spins` requires `latest_run_index in trend.run_indices` before `closed` is even consulted" to justify why no dedicated hand-resolution-closure step is needed. In `convergence_diagnosis.py`, `_region_spins` actually evaluates `not trend.closed` first (its own docstring says so: "The closed check comes first"), so `closed` is consulted before the presence check, not after. The design conclusion still holds — it's an `and` of independent booleans, so evaluation order doesn't change the result — but the stated justification inverts the code it cites.
  - Fix: correct the Architecture sentence to say `closed` is checked first but the outcome is order-independent, rather than claiming presence is checked before `closed`.
