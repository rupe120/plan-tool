- HIGH `[existing-relation-retarget-boundary]`: `edit-row` relationship authority conflicts across the bundle: Architecture says “This vocabulary does not rewrite an existing relation regardless of decision state,” Risks excludes “any broader relation change,” and step 2 (`Build bounded stage-envelope feedback context`) and step 3 (`Atomically apply authorized row, prose, and ordering operations`) say existing relations are rejection facts; step 1 (`Define closed stage-envelope operations`) and its acceptance/tests prohibit only `DecisionRow.anchor` and `AssumptionRow.consuming_plan_ids`. At HEAD, `roadmap_relations.py:extract_declared_relations` identifies several other editable relation fields, while `ComponentRow.store_ids` is a relation not even represented there, so implementations can either allow or refuse those retargets.
  - Fix: Define one complete existing-relation field set that `edit-row` must preserve, then bind, merge, and test every member under that rule.
- HIGH `[baseline-enrollment-prefix-recovery]`: `--enroll-baselines` requires one command to record a baseline for every member of a contiguous prefix and refuses an “already enrolled stage,” but Architecture specifies only a per-stage non-Plans bootstrap or a Plans-plus-seed bootstrap. Step 4 (`Enroll a trusted canonical baseline`) covers intact enrollment and a Plans baseline/seed interruption, but its implementation, tests, and acceptance criteria do not define recovery for an interruption between two prefix baseline records; a retry can face both an enrolled prefix and an unfinished suffix with no valid continuation.
  - Fix: Make a whole enrolled prefix one recoverable bootstrap set, including seed state when applicable, and require enrollment recovery before its already-enrolled checks.
- HIGH `[stage-source-admission-race]`: `normal stage source admission` promises that every post-enrollment direct semantic edit is detected, but Architecture and step 5 (`Route re-entered stages through bounded feedback or no-op re-gating`) require an immediately-before-write identity recheck only for `--revise-feedback`; the listed tests likewise cover only the local route. At HEAD, `roadmap.py:_load_predecessors` snapshots all selected artifacts before backend work and `roadmap.py:_run_roadmap` writes them later, while `roadmap_revision_publish.py:roadmap_writer_guard` is advisory, so a direct edit after normal admission can be overwritten or omitted from a later stage’s gate input.
  - Fix: Retain and recheck baseline bindings for every normal-route selected and file-backed upstream artifact before publishing or passing it to a later stage, and refuse a changed source without a write.
- MEDIUM `[store-reference-context]`: Step 2 (`Build bounded stage-envelope feedback context from the authority matrix, selected isolated row-prose spans, declared relations, and plan ordering`) says selected removals receive incident relation facts from `roadmap_relations.py:extract_declared_relations`, but `_component_records` omits `ComponentRow.store_ids`. A feedback-targeted Store removal therefore lacks the incoming component references that `roadmap_gates.py:check_store_definitions` needs; the operation can reach a deterministic gate rejection after the backend call, which contradicts the **Risks** “Incomplete feedback context” requirement to derive the minimum context from gate obligations.
  - Fix: include declared Component-to-Store references in the bounded relation context and cover referenced and unreferenced Store removals.
- HIGH `[feedback-input-write-race]`: Step 4 deliberately excludes `feedback` from source identity, step 3 preserves unselected feedback only from its preflight snapshot, and step 5’s pre-write checks revalidate only that non-feedback identity. A reviewer can add or change valid feedback after context/preflight while the advisory `roadmap_writer_guard` is held; the bounded stage or local candidate then writes its stale snapshot and drops that reviewer input.
  - Fix: Define a separate feedback-snapshot check for both bounded publication paths that refuses without a write when reviewer-owned feedback changes after preflight, and cover added, changed, and reopened feedback rows.
