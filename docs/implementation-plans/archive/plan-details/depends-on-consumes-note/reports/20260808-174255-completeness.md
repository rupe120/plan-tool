Steps 1, 2, 3, 4, and 6 each map to at least one acceptance-criterion bullet; step 5 does not, so nothing in the plan's exit checklist confirms this deliverable landed.
  - Fix: add an acceptance criterion stating the withdrawn audit-trajectory-instrumentation fixture exists and each of its four cross-cluster edges is either annotated or visibly silent, never indistinguishable from a justified edge.
- MEDIUM `[blank-note-representation]`: The plan's central design rule is that "a depends_on edge either carries a note or it does not" (Architecture), with presence as the only checked property — but no text says what a blank or declined answer actually gets stored as. Architecture says a manual-wizard "blank answer is accepted exactly like a proposed edge with no note," and a Claude-proposed "edge with no note is accepted unchanged" — neither states whether that means the key is left out of `depends_on_notes` (true absence) or written in as an empty string (a dict key present with `''`), which would be a third state that is neither clearly "has a note" nor clearly "does not," undermining the presence-only premise and making step 4's interactive review show an edge that looks noted but is blank.
  - Fix: state explicitly, for both the Claude-proposal round-trip and the manual wizard, that a blank or declined answer omits the key from `depends_on_notes` entirely rather than storing an empty string, so presence stays unambiguous everywhere the field is written.
- MEDIUM `[merge-outbound-note-agreement-scope]`: The merge (outbound) row keeps a collapsed edge's note "only when every merging member's edge to that same antecedent carried identical note text," but a merge group commonly has partial overlap — some members depend on the shared antecedent, others never reference it. The row doesn't say whether "every merging member" means every member of the whole group (so a member with no edge to that antecedent at all forces the note to clear) or only the subset that actually declared that edge (so only their agreement matters). The two readings give very different practical outcomes — notes routinely surviving partial-overlap merges versus almost never surviving any merge — and step 2's detail file needs one meaning to implement against.
  - Fix: pin the merge (outbound)/(inbound) rows to say explicitly that only the merging members which declared an edge to the shared antecedent must agree on its note text; members without that edge don't count against agreement.
- MEDIUM `[escalate-split-note-carry]`: Step 2 lists tests only in `tests/test_create.py`, `tests/test_scope_out.py`, and `tests/test_detail.py`, but `_apply_step_split` — the function the Architecture's "split" row governs — has a third real caller the plan never names: `launcher.py`'s `escalate_to_split`, the mid-run split bridge a MIXED-STEP purity finding can trigger during `run` (`new_steps = _apply_step_split(plan.steps, step_id, replacements)`). The note-carry logic lives inside the shared function body, so this path almost certainly inherits correct behavior automatically — but nothing proves it, unlike the `detail.py` split/merge path, which gets an explicit `test_detail.py` mention. This is the same "cover every caller of the shared function" rule the plan already applies across `create`'s interactive split and `detail`'s post-hoc split.
  - Fix: add `tests/test_launcher.py` to step 2's files and testing scope, proving a mid-run `escalate_to_split` split carries `depends_on_notes` the same way the `create`/`detail` split paths do — and apply the same check to any other direct caller of `_apply_step_split`/`_apply_step_merge` found while implementing, not only this one.
- MEDIUM `[canonical-extraction-note-exclusion]`: The Testing section's "Negative-space fixture" bullet proves `depends_on_notes` stays absent for only two of the three paths Architecture calls deliberately note-less — "a scope-out's carved-out seed and a `reground` run" — and skips `plan_tool/canonical.py`'s `extract_canonical_steps`, which Architecture states just as explicitly carries "zero `depends_on_notes` by construction, deliberately." With no matching negative-space test, nothing catches a future change to `extract_canonical_steps` or its `Step` conversion in `create.py` (the `depends_on=cs.depends_on`-style copy) if it starts inventing empty note entries instead of leaving the field absent.
  - Fix: extend the negative-space fixture bullet to cover all three deliberately note-less paths named in Architecture — canonical extraction, the carved-out seed, and reground — not just the latter two.
