## Why

`docs/ROADMAP_WALKTHROUGH.md` and `docs/ROADMAP_DEMO_ORCHESTRATION.md` are the two narrative guides an operator runs commands from, and both currently walk a stage-4 write that, after steps 1–10, no longer happens: the walkthrough's stage table names `04-roadmap.md` and `seeds/` together as one artifact holding "one draft seed per plan row" (`docs/ROADMAP_WALKTHROUGH.md`, § "2. Generate the roadmap"), and its promotion section assumes accepted seeds already exist the moment stage 4 finishes (§ "6. Promote accepted draft seeds, or create directly from them"). The demo orchestration doc repeats the same shape in its own artifact table and adds two more instances of the same claim: a gate count that included the now-removed provenance gate, and a `seeds/`-prefixed worked example for a *fresh* roadmap that should use the renamed directory. Both docs' example `create --from-existing` commands still point at the pre-rename `seeds/` prefix for a brand-new roadmap. Left uncorrected, an operator following either doc top to bottom hits `--apply` refusing every draft as `missing` (step 6's own acceptance criterion), with no earlier step in the doc explaining why or what command fixes it.

`docs/ARCHITECTURE.md`'s Roadmap paragraph and `CAPABILITIES.md`'s `architecture-roadmap` entry are reference material rather than a runnable script, but they repeat the identical claims in prose form: a five-module count that step 3's new `plan_tool/roadmap_seed_manifest.py` invalidates, an unconditional "prints runnable `create --from-existing` lines" claim that step 9 makes conditional on a plan's draft classifying `current`, and — in `ARCHITECTURE.md` specifically — a sentence describing the plain `roadmap <slug> --from-existing <concept.md>` call as producing "draft seeds at each plan row's `draft_seed_path`," which step 9's own acceptance criterion (a stage-4 write completing "with zero seeds materialized") makes false. Because these are the two docs a future session reads to understand the module's shape before touching it, leaving any of these three claims in place invites a later reconcile or audit round to flag a contradiction between the doc and the code steps 1–10 actually landed.
