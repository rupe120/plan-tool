# Step 3 — Add the `worktree` command group (`add` + `list`) and wire it into the CLI

## Summary

Add a new per-intent command module `plan_tool/cli/worktree_cmd.py` exposing a `worktree` command group with two verbs: `worktree add <plan> [--branch B] [--clone]` (provision or reuse an isolated workspace at the plan's deterministic per-slug path, on the plan's branch) and `worktree list` (report every registered plan's workspace — kind, branch, path, dirty/clean). The module composes the step 1 git primitives (`worktree_add`, `worktree_list`, `clone_repo`) with the step 2 pure path/target helpers (`derive_worktree_path`, `classify_target`) and the branch-awareness name helpers (`derive_branch`, `default_branch`), adding the impure glue those leaves deliberately left out: branch resolution, start-point resolution, the reuse-vs-fail tiebreak at the derived path, and kind dispatch in `list`. The key design rule: **the branch is born inside the provisioning call** (never a main-tree `switch -c`), and **branch + start-point are always defined** so a bare `worktree add <plan>` works on a local-only repo with no remote. Wiring follows the fixed new-subcommand recipe across `app.py`, `parser.py`, `__init__.py`, the generated CLI reference, and the help golden. On green, `plan-tool worktree add <plan>` provisions a worktree on the slug-derived branch and prints a `cd` hint; `plan-tool worktree list` reports it; the new unit tests and the package-surface/cli-reference drift guards pass.

## Why

- **Steps 1 and 2 ship the primitives but no entry point.** Step 1 added policy-free git wrappers (`worktree_add`/`worktree_list`/`clone_repo`) to `plan_tool/cli/gitcommit.py`; step 2 added the pure path/target leaf `plan_tool/worktree.py` (`derive_worktree_path`, `classify_target`). Neither resolves a branch, picks a start-point, decides reuse-vs-fail, or dispatches worktree-vs-clone — all of which their Deferred blocks explicitly assign to this step. Without this command group there is no way for an operator to provision a workspace.
- **The branch/start-point resolution is the key new logic.** `worktree_add`/`clone_repo` consume an already-resolved `branch` and `start_point`; this step is where those become defined for every config state, so `plan-tool worktree add <plan>` "just works" under the project-default (branch-awareness OFF, no remote) without the operator passing flags.
- **`list` needs the impure half of the tiebreak.** `classify_target` reports only what is on disk; deciding *which kind* of workspace sits at a derived path (worktree via the git registry, clone via a `.git` directory) and reporting its branch/dirty state needs `worktree_list` and a `.git` probe — kept out of the pure leaf on purpose.

## Implementation

### `plan_tool/cli/worktree_cmd.py` — module shape and imports

- **Model the module on `plan_tool/cli/runs.py`** — the closest existing group-with-subactions: its `register` builds one top-level parser, calls `p.add_subparsers(dest="action", required=True)`, adds one sub-parser per verb, and returns `{"runs": cmd_runs}`; `cmd_runs` dispatches on `args.action`. Mirror that exactly for `worktree`.
- **Import only cycle-free leaves + domain modules** (never `plan_tool.cli.app`):
  - `from plan_tool.cli.context import _load_context`
  - `from plan_tool.cli.parser import Handler`
  - `from plan_tool.locator import resolve_plan_for_context, slug_from_filename`
  - `from plan_tool.worktree import derive_worktree_path, classify_target, TargetState` (step 2)
  - `from plan_tool.cli.gitcommit import worktree_add, worktree_list, clone_repo, default_branch, branch_exists, current_branch, working_tree_dirty, WorktreeEntry` (step 1 + existing; `default_branch`/`branch_exists`/`current_branch`/`working_tree_dirty` already live in `gitcommit.py`)
  - `from plan_tool.project_config import branch_awareness_enabled, branch_prefixes, derive_branch`
  - `from plan_tool.style import info, error, success` (console output)

### `cmd_worktree(args)` — group dispatcher

- **Dispatch on `args.action`:** `"add"` → `_cmd_worktree_add(args)`, `"list"` → `_cmd_worktree_list(args)`. Return the verb handler's exit code. `dest="action"` is `required=True`, so argparse rejects a bare `plan-tool worktree` before dispatch.

### `_resolve_branch(repo_root, slug, explicit)` — always-defined branch name

- **Precedence, returning a non-empty `str` in every case:**
  1. `explicit` (`--branch B`) is truthy → return it.
  2. `branch_awareness_enabled(repo_root)` is true → return `derive_branch(slug, branch_prefixes(repo_root))` (the `prefixes[0] + slug` canonical name).
  3. Otherwise (branch-awareness OFF — the project default) → return `slug` (the deterministic slug-derived fallback).
- **Clause (2)'s empty-prefix case is unreachable, not handled here:** `branch_prefixes` defaults to `["plan/"]` and rejects an empty list, so `derive_branch` never indexes an empty sequence. Clause (3) keys on awareness-OFF only.

### `_resolve_start_point(repo_root)` — always-defined start point

- **Return `default_branch(repo_root) or "HEAD"`.** `default_branch` returns `None` on a local-only repo with no `origin/HEAD` and no `PLAN_TOOL_DEFAULT_BRANCH` (the common case, and every `tmp_path` test repo), so the `"HEAD"` fallback is what makes a bare `worktree add` succeed there. Never pass `None`/empty to the primitives — `git worktree add -b <branch> <path>` with an empty start-point fails cryptically.

### `_cmd_worktree_add(args)` — provision or reuse

- **Resolve inputs:** `ctx = _load_context(args)`; `path = resolve_plan_for_context(ctx, args.name)`; `slug = slug_from_filename(path)` (never `None` — defaults to the stem); `branch = _resolve_branch(ctx.repo_root, slug, args.branch)`; `start_point = _resolve_start_point(ctx.repo_root)`; `target = derive_worktree_path(ctx.repo_root, slug)`.
- **Reuse-vs-fail tiebreak before provisioning** (`_reuse_or_fail`, see below). If it returns "reuse" → print the path + `cd` hint and return 0 (idempotent). If "fail" → print a clear error and return non-zero. If "provision" → continue.
- **Pick the create flag from branch existence:** `create = not branch_exists(ctx.repo_root, branch)`. A new branch is born off `start_point` (`-b`); an existing branch is checked out as-is.
- **Provision by kind:**
  - default (worktree): `rc, tail = worktree_add(ctx.repo_root, target, branch, create=create, start_point=start_point)`.
  - `--clone`: `rc, tail = clone_repo(ctx.repo_root, target, branch=branch, create=create, start_point=start_point)`.
- **On non-zero `rc`:** print `error(...)` with the stderr `tail` (e.g. git's same-branch-twice refusal surfaces here as a clean message) and return the rc (non-zero). Never raise.
- **On success:** print the absolute `target` path and a `cd <target>` hint via `info`/`success`; return 0.

### `_reuse_or_fail(repo_root, target, branch, *, clone)` — the impure half of step 2's tiebreak

- **Use `classify_target(target)` for the filesystem state, then a git-aware health probe:**
  - `TargetState.ABSENT` or `TargetState.EMPTY` → `"provision"` (an empty existing dir is a valid `worktree add`/`clone` target).
  - `TargetState.NOT_A_DIR` → `"fail"` (a file/symlink sits at the path).
  - `TargetState.NON_EMPTY` → probe whether it is a **healthy workspace of the expected kind on the expected branch**:
    - worktree path: a `worktree_list(repo_root)` entry whose resolved `path` equals `target` **and** whose `branch` equals the expected `branch` → `"reuse"`.
    - clone path: `(target / ".git").is_dir()` **and** `current_branch(target) == branch` → `"reuse"`.
    - anything else (foreign dir, stale/pruned admin, wrong branch, wrong kind) → `"fail"` with a message naming the path.
- **This single rule resolves "reuse existing" and "validate-and-fail on a non-empty target"** — the two behaviors the plan calls out as one decision.

### `_cmd_worktree_list(args)` — enumerate + dispatch by kind

- **Enumerate registered plans:** iterate `ctx.entries`; for each entry derive `slug` and `target = derive_worktree_path(ctx.repo_root, slug)`. Skip entries whose `classify_target(target)` is `TargetState.ABSENT`.
- **Build the worktree registry once:** `wt_by_path = {Path(e.path).resolve(): e for e in worktree_list(ctx.repo_root)}`. The main working tree never enters the report because every plan's `target = derive_worktree_path(ctx.repo_root, slug)` resolves under the out-of-repo `worktree_base` (step 2 guards the base outside the repo), so no plan's target can equal `ctx.repo_root.resolve()`. Dropping the `ctx.repo_root.resolve()` entry is optional defensive code, not a load-bearing filter.
- **`_classify_workspace_kind(target, wt_by_path)` per plan:**
  - `target.resolve()` in `wt_by_path` → kind `worktree`, branch from the `WorktreeEntry.branch` (already `refs/heads/`-stripped, `None` when detached).
  - else `target` exists and `(target / ".git").is_dir()` → kind `clone`, branch from `current_branch(target)`.
  - else → not a recognized workspace; skip.
- **Report per workspace:** the slug/plan, kind, branch, absolute path, and dirty/clean from `working_tree_dirty(target)`. Print a "no workspaces" line and return 0 when nothing was provisioned. `list` spends no Claude, mutates nothing, and always returns 0.
- **Do not consolidate `working_tree_dirty`** — use `gitcommit.py:working_tree_dirty`, not `run_cmd.py`'s separate `_working_tree_dirty` (that one belongs to `run`'s `--commit` helper).

### `register(subparsers)` — the group parser

- **Build the group:** `p = subparsers.add_parser("worktree", help="provision and inspect isolated per-plan workspaces (worktrees / clones)")`; `sub = p.add_subparsers(dest="action", required=True)`.
- **`add` verb:** `p_add = sub.add_parser("add", help="provision (or reuse) the plan's workspace on its branch")`; positional `name`; `--branch` (`dest="branch"`, default `None`); `--clone` (`action="store_true"`, default `False`).
- **`list` verb:** `p_list = sub.add_parser("list", help="report every plan's workspace: kind, branch, path, dirty state")`; no positional.
- **No `-y/--yes` / `--fail-on-findings` parents** — neither verb is destructive or findings-gated (step 4's `remove`/`prune` add the confirm parent). Keep the surface minimal.
- **Return `{"worktree": cmd_worktree}`** — one handler for the group; the verb fan-out is internal to `cmd_worktree`.

## Acceptance criteria

- `plan-tool worktree add <plan>` provisions a git worktree at `derive_worktree_path(repo, slug)` on the resolved branch, the branch created+checked-out inside the add (`-b` off the resolved start-point — default-branch name, else `"HEAD"`), prints the path + a `cd` hint, and returns 0. The bare command succeeds on a local-only repo with no remote/default-branch config.
- Branch resolution is always defined: `--branch B` wins; else `derive_branch` when branch-awareness is ON; else the slug-derived fallback.
- Re-running `worktree add` for the same plan reuses the existing healthy workspace (rc 0), while a foreign/broken non-empty target dir returns non-zero with a clear message and no overwrite.
- `plan-tool worktree add <plan> --clone` produces a clone (a standalone repo dir whose `.git` is a directory) on the resolved branch; rc 0.
- `plan-tool worktree list` reports every registered plan's provisioned workspace with kind (`worktree`/`clone`), branch, path, and dirty/clean; it returns 0 even with no workspaces.
- Git failures (same-branch-twice, bad path, non-git) surface clean messages and a non-zero exit only on failure-to-complete; nothing raises.
- `plan_tool.cli.cmd_worktree` resolves; `worktree` appears in `--help` in canonical order; `docs/cli/worktree.md`, the `docs/cli/README.md` row, and `tests/cli/package_surface_help.golden.txt` match the regenerated/re-baselined output (drift guards green).
