  - Fix: assign guarded recovery before every participating writer’s first roadmap or sidecar read, with one shared recovery result for writers and views
- MEDIUM `[seed-state-path-alignment]`: Architecture permits allowlisted `modify-row` changes while promising the sidecar changes “status only”; a `PlanRow` has a mutable `draft_seed_path`, and a targeted change to it would make the canonical plan point to a new draft while `roadmap_seed_state.validate_seed_state` retains the old path. `roadmap_seed_manifest.classify_draft_seeds` reads the new plan path, while `roadmap._invalidate_roadmap_seeds` can instead copy a candidate path, so steps 5, 6, and 8, Input, Testing, and the seed-state acceptance criterion permit incompatible outcomes.
  - Fix: either reject targeted `draft_seed_path` changes as structural or define the atomic sidecar and old-draft handling that preserves the no-draft-prose guarantee
- MEDIUM `[patch-operation-cardinality]`: Steps 3 (`Define revision collection names… operation identities…`) and 5 (`Enroll full-stage artifacts… parse only existing-row modification and feedback-response patches`) define ordered patch operations and exactly-one selected-feedback responses, but Architecture, step 6, Testing, and the acceptance criteria never define duplicate or unmatched `modify-row` and `replace-prose` operations. Two patches for one row can reasonably mean first wins, last wins, sequential application, or rejection, and the expected prose digest does not choose among them.
  - Fix: define cardinality and pairing rules for row and prose operations, reject or sequence duplicates deterministically, and add an acceptance case for that policy
- HIGH `[session-candidate-digests]`: Architecture puts the session-record candidate in the staged candidate set and says that record carries candidate digests, while recovery retains a checkpoint only when those digests match. Steps 3, 7, 8, and 11, Testing’s checkpoint-mismatch cases, and the published-session acceptance criterion never say whether the record digests its own bytes or whether the marker or committed tree verifies them; self-digesting is not directly possible, while excluding it leaves the review record outside the stated recovery check.
  - Fix: define the authoritative candidate-digest set and the separate verification source for the session-record bytes, then use that rule for checkpoint and recovery validation
