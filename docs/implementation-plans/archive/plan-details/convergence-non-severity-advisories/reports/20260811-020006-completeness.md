With no deterministic pick rule (most passes recurred, largest current count, lowest id, …), two audits over the identical saved history could print different seams, which cuts against the "fully deterministic" bar the plan sets for the sibling edit-drift check.
  - Fix: add an acceptance criterion (and note in step 3) naming the deterministic tie-break used to choose one seam when several qualify at once.
- MEDIUM `[edit-drift-new-finding-definition]`: Step 4's "new" predicate — "a finding is new in the newest pass if its id is absent from the immediately prior pass" — uses raw id equality, but this plan's own reliance on "the existing convergence report-history matcher" as a fallback exists precisely because a subjective audit mints a fresh content-hash id whenever it rewords a finding (see `convergence.py`'s own documented reasoning for `max_stall_rounds`). So a finding that is really the same open issue restated will already read as "new" under the raw-id check, leaving "new" close to meaning "every material finding in the newest pass" — which may still work as a denominator but is not what the word promises a reader.
  - Fix: state plainly whether "new" is meant to exclude only byte-identical repeats (near-vacuous, and say so explicitly) or should also run the shared identity chain against the immediately prior pass before counting a finding as new.
