So one stale target silently kills the whole advisory, exactly what Testing item 3 and the acceptance criterion "never silently voiding the whole advisory" say must not happen, and exactly the renumbering/split/merge risk the Problem statement names as the reason this design reuses `_matches` in the first place.
  - Fix: extend Architecture point 5 (and Testing items 3–4) so a finding is also dropped from `consensus_targets`/`material_finding_ids` when its agreed target step id is missing from the current `declared_step_ids`, not only when per-round targets disagree or are missing — so the caller pre-filters this case before calling `evaluate_arm_clustering`, instead of letting its existing all-or-nothing check silently erase the whole result.
