- MEDIUM `[one-reader-path-scope]` [confidence: limited]: The plan states "Every command that reads roadmap content resolves it through `load_accepted_version`", and the acceptance criterion says "No command reads or writes roadmap content outside `.roadmap-versions/`". Neither holds as written, and the plan never says what "roadmap content" covers.
  - Candidate-lifecycle commands read candidate versions, not the accepted head. `roadmap_candidate_run.py` uses `stored_artifact_path(..., candidate_version_id, ...)`, and `--compare` resolves its target through a candidate loader.
  - `seed-state.json` and the feedback ledger live at the roadmap root, and the plan keeps them.
  - `INDEX.md` and the resume file are also written outside `.roadmap-versions/`.
  - Step 11's guard only covers `RoadmapStage.artifact_path`, the resume file and `INDEX.md`. It does not cover the broader claim.
  - Two implementers could therefore pass or fail the criterion differently. One would count the root sidecars and `INDEX.md` as violations, the other would not.
  - Fix: Define "roadmap content" once as the four stage artifacts' bodies. Restate the reader rule as "accepted-head readers use `load_accepted_version`; candidate readers use stored-version loaders". Name `seed-state.json`, the ledger, `INDEX.md` and the resume file as the only permitted non-store files. Reconcile the Architecture "One reader path" bullet, the acceptance criterion, and the step 11 guard to that wording.
- HIGH `[legacy-folder-first-run]` [confidence: limited]: Step 3 turns the stage command into "first run: no accepted head, so publish a root version". The plan never says what happens when the folder has no accepted head but already holds legacy top-level `01-domain.md`–`04-roadmap.md`. That is an unenrolled legacy roadmap, which step 6 and step 11 stop reading. The plan's `## Out of scope` rules out tool-driven migration, but it does not say what the stage command does with such a folder.
  - If the command runs anyway, it silently publishes a second, different root next to the old files. That recreates the two-copy state this plan removes.
  - If it refuses, the plan does not say so, and no test locks it in.
  - Fix: Add an explicit stage-command rule: a roadmap folder with no accepted head but existing top-level `0N-*.md` files refuses with a named error pointing at hand conversion. Add that refusal to step 3's scope and to the Testing list.
- MEDIUM `[resume-file-integrity]` [confidence: limited]: The Resume design covers a digest mismatch but not an unreadable resume file. A crash during the write, or a hand edit, can leave the file corrupt or malformed. Step 2 (resume-file module) owns the file, and step 3 (stage run) is its only reader. The plan does not say whether the run refuses with a named error or discards the file and restarts from stage 1. The first keeps the "resumes without repeating gate-clean stages" promise and the second silently repeats paid model calls. This is an unchosen behavior in a property the acceptance criteria name.
  - Fix: Choose one behavior for an unreadable or structurally invalid resume file. Prefer a refusal naming the file, or an explicit discard with a warning. State it in the Resume bullet, and add one Testing bullet.

- MEDIUM `[index-md-write-sites]` [confidence: limited]: The `INDEX.md` write sites have no single owner and one gap. The Architecture bullet writes `INDEX.md` after root publication, "after the head commits, the resume file is deleted and `INDEX.md` is written". Step 3's title lists the resume-file deletion but not that write. Step 4 builds the renderer. Step 5 hooks "every command that commits a version, candidate admission, terminal resolution, supersession, or accepted-head write".
  - It is unclear whether step 3 or step 5 owns the root-publication call, so it could be left to neither.
  - A crash after the head commits but before `INDEX.md` lands leaves a roadmap with no index. Nothing then rewrites it, because the post-head stage refusal commits nothing and the other commands only write `INDEX.md` after a commit.
  - The acceptance line "`INDEX.md` is written as specified" therefore cannot hold in that window.
  - Fix: State that step 5 owns every `INDEX.md` call, including root publication. Add that the post-head stage-command refusal path, which already deletes a leftover resume file, also rewrites `INDEX.md` best-effort. Add a Testing bullet for the head-committed, no-`INDEX.md` crash gap.
- MEDIUM `[resume-file-integrity]` [confidence: limited]: The Resume design covers a digest mismatch but not an unreadable resume file. A crash while the file is being written, or a hand-edited file, can leave it corrupt or malformed. The plan does not say whether the stage run refuses or discards it and restarts from stage 1. Both choices are safe, but they give materially different operator outcomes: a refusal points the operator at the file, while a silent restart repeats the held stages' backend calls.
  - Fix: Add one sentence to the Resume bullet choosing the behavior for an unreadable or schema-invalid resume file. Refusing with a named error that names the file matches the digest-mismatch behavior.
