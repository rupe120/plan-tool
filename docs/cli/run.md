# `plan-tool run`

## Usage

```
plan-tool run [-h] [-y] [--max-iterations N] [--iteration-budget SECONDS] [--time-budget SECONDS] [--max-stall-rounds N] [--allow-drift] [--no-auto-reconcile-on-drift] [--no-triage] [--include-info] [--no-collision-sidecar] [--iterate | --no-iterate] [--reconcile] [--step STEP] [--all] [--accept] [--max-steps N] [--commit] [--archive] [--skip-merge-check] [--switch-branch] [--mode {run,check,optimize,document,test,security,lint}] [--detail-grade {run,jira}] [--dry-run] [--allow-missing-parent] [--no-save] [--no-walk] [--reuse | --no-reuse] [--reuse-id STEM] [name]
```

## Arguments

| Argument | Description |
| --- | --- |
| `name` | plan name — slug, filename stem (e.g. 1-my-feature), or filename.md. Omit (or pass a name that doesn't resolve) to pick interactively from the plans that still have open steps. |

## Options

| Option | Default | Description |
| --- | --- | --- |
| `-y`, `--yes` | off | auto-accept Y/N confirmation prompts (proceed with the offered action without asking). Useful for scripted/unattended runs. |
| `--max-iterations` `N` | `3` | cap the convergence loop at N iterations even if findings keep changing (default: 3). Ignored when --no-iterate is set. |
| `--iteration-budget` `SECONDS` | `1800` | debounced no-progress deadline in seconds: stop the convergence loop only once SECONDS pass with no forward progress at all (default: 1800). Resets on every round and every apply_finding call, so one long claude call — even 15-20+ minutes — never trips it on its own; see --time-budget for a true total-elapsed cap. Ignored when --no-iterate is set. |
| `--time-budget` `SECONDS` | — | cooperative wall-clock cap (#123): stop the convergence loop cleanly at the next round boundary once SECONDS of total elapsed time pass — even while still converging — so a long op lands before an external execution ceiling instead of being killed mid-call. Exits 0 with a resume hint. Unlike --iteration-budget (a no-progress stall deadline), this is a hard total-elapsed cap. Falls back to PLAN_TOOL_TIME_BUDGET; default off. Ignored under --no-iterate. |
| `--max-stall-rounds` `N` | `2` | stop the convergence loop after N consecutive rounds whose open-finding count fails to shrink (default: 2). This is the ID-agnostic backstop for a subjective claude audit that re-phrases the same findings each round (fresh ids defeat the marginal / converged checks). Pass 0 to disable. Ignored when --no-iterate is set. |
| `--allow-drift` | off | opt back into the legacy 'warn but proceed' behavior when a watched file's content changes mid-iteration. Default: the loop checks drift BEFORE each apply (halts without spending claude tokens if drift detected) AND AFTER (keeps the apply's edits but halts subsequent applies if drift happened during the apply call). Token-preserving by design -- no revert, just halt + flag for `git diff` review (task #30). Pass --allow-drift only when you're sure the drift is expected (e.g. an automated formatter touching files in step.files during iteration). |
| `--no-auto-reconcile-on-drift` | on | skip the auto-reconcile pass that fires when drift halts the iteration loop. Default: when drift is detected, plan-tool runs `reconcile` against the step(s) that own the drifted file(s), saves the findings, and prints a structured summary inline with the halt (Lesson 13: audit beats observe). Pass this flag to suppress that extra claude call -- useful in CI runs that prefer a minimal stderr footprint, or when you'll inspect drift manually via `git diff` and `plan-tool run --mode reconcile`. |
| `--no-triage` | on | skip the impact-weighted triage gate on findings. Default: when a finding carries impact/complexity tags (the plan-audit prompt's trailing ``(impact=…, complexity=…)`` on conceptual findings; the reconcile prompt's ``Impact:`` / ``Complexity:`` fields), the iteration loop skips applies whose complexity strictly exceeds their impact (low+medium, low+high, medium+high) -- those findings are reported on stderr and dropped from the open-set so convergence short-circuits when only triaged findings remain. Findings without triage tags (deterministic checks, untagged output) default to apply. Pass this flag to force-apply every finding regardless of triage tags -- useful for completeness sweeps where you want to land every applicable edit. |
| `--include-info` | off | apply info-severity findings too. Default: info findings are advisory (a concept too vague to audit, a heuristic hit, a detail-only path) and are excluded from the apply loop -- they're still reported in the deferred summary, just not auto-applied. Pass this to spend claude tokens applying them as well. |
| `--no-collision-sidecar` | on | skip the change-collision sidecar pause when drift fires during apply_finding. Default: when drift is detected post-apply, plan-tool saves claude's edits to `<stem>-change-collision<ext>` next to each modified original, restores originals to pre-apply state, and pauses interactively for the user to merge with their preferred tool (vimdiff, `code --diff`, meld, etc.). Pressing Enter at the prompt continues the iteration loop against the merged state; Ctrl-D / typing 'abort' halts as today. Pass this flag to revert to the legacy 'keep claude's edits on disk, review via git diff' behavior -- useful when scripting or piping to a CI consumer that doesn't expect sidecar files. Headless runs (-y or non-TTY) auto-skip the pause and fall through to halt regardless of this flag, since there's no human to merge. |
| `--iterate`, `--no-iterate` | off | no effect on run; retained for script compatibility. --reconcile rejects --iterate. Use separate reconcile-code invocations after reviewing and committing corrections. |
| `--reconcile` | off | legacy form of 'plan-tool reconcile-code' (kept working). Audit code against the plan (plan is canonical) and land code edits inline; findings whose root cause is in the plan are short-circuited with [REDIRECT] pointing at 'plan-tool detail --reconcile'. Mutually exclusive with --mode and --iterate. |
| `--step` `STEP` | — | run a specific step by id (default: current or next runnable) |
| `--all` | off | sweep every runnable step in one invocation. Loops `next runnable -> run` until the plan completes, a step exits non-zero, or --max-steps N is hit. Implies -y. Mutually exclusive with --step and review-mode --mode values; only --mode run (default) is accepted. |
| `--accept` | off | with --step N: mark a hand-fixed step done with no backend call. Requires a clean working tree apart from the plan file and its lessons log, runs the plan's test_command and the step's gate, and writes nothing unless all pass; then applies the ordinary done-and-advance and the lessons entry. With --commit, commits only the plan and lessons files. Refused unless the step is current and committed, and when nothing certifies it. Not combinable with --all, --reconcile, --dry-run, --archive, --detail-grade, or a review --mode (--iterate warns). |
| `--max-steps` `N` | — | for --all: cap the sweep at N steps (default: unlimited, bounded by plan length). Ignored without --all. |
| `--commit` | off | after each step goes green, stage all changes (git add -A) and create one commit with subject 'plan(<slug>): step N green — <title>'. Applies to execution (--mode run) at either scope (single-step or --all); requires a clean working tree up front; off by default. No-ops (with a warning) under --dry-run or review/--reconcile modes — nothing to commit. |
| `--archive` | off | for --all or a completing --step run: when the step takes the plan to N/N done, move it to archive/ (file + plan-details/) and deregister from the manifest, then print a 'plan-tool register' undo hint. Off by default. |
| `--skip-merge-check` | off | skip the pre-run check that you are off the default branch and that the plan and every committed step's detail file are on its remote ref (origin/main). The check is on by default; a repo can turn it off with run.require_merged_plan=false in .plan-tool/config.json or PLAN_TOOL_REQUIRE_MERGED_PLAN=0. |
| `--switch-branch` | off | for branch-aware repos: on an unowned branch whose plan expects a different branch, switch to (creating if missing) the plan's expected branch on a clean tree before running; refuses on a dirty tree. No effect when branch awareness is off. |
| `--mode` `{run|check|optimize|document|test|security|lint}` | `run` | prompt mode (default: run). 'run' executes the step and advances the plan; other modes are read-only inspections that leave the plan unchanged. Review modes parse claude's `## Findings` block and print a verdict; a completed audit exits 0 even with CRITICAL findings. |
| `--detail-grade` `{run|jira}` | `run` | which detail artifact the step executes from (default: run). `jira` reads the compact jira-grade artifacts under plan-details/<plan_slug>/jira/ and fails before any backend call — including under --dry-run — when one is missing or off-contract; the run-grade detail file is never substituted. Execution only: rejected with a review --mode or with --reconcile. |
| `--dry-run` | off | render the prompt and print it; do not invoke claude |
| `--allow-missing-parent` | off | skip the pre-flight check that refuses steps whose declared files have a missing parent directory under the repo root. Use when the step legitimately creates files under a path that doesn't exist yet (e.g. a new module directory). |
| `--no-save` | off | for --reconcile: skip persisting the audit findings to plan-details/<slug>/reports/. Implies --no-walk. Has no effect otherwise. |
| `--no-walk` | off | for --reconcile: skip the interactive walk over the audit findings. The findings are still saved unless --no-save is also set. Has no effect otherwise. |
| `--reuse`, `--no-reuse` | — | for --reconcile: reuse a saved run-reconcile's findings instead of running a fresh claude audit, when the save is fresh (plan AND code fingerprints still match). Default (unset): prompt interactively, auto-accepting under --yes / non-TTY stdin. --reuse always reuses a fresh save; --no-reuse always re-audits. A stale save is never reused — it declines to a fresh audit with a staleness note. |
| `--reuse-id` `STEM` | — | pin reuse to a specific saved run-reconcile by filename stem (the bare `<ts>` or full `<ts>-run-reconcile` form); default: newest matching save for this step. An unresolved id prints a note and falls back to a fresh audit. |
