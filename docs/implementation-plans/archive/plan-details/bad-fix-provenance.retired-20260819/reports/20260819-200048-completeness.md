- HIGH `[remedy-event-order]`: The Architecture and Input call a remedy “intervening,” step 1 promises ordered history, step 5 matches “earlier” notes, and acceptance requires a matching intervening note, but none defines a persisted event order or equal-time tie-breaker. `completeness_report:_reserve_report_timestamp` can advance a colliding report time before `save_review`, while `convergence_diagnosis:load_report_history` orders by `created_at`, so a later remedy can appear earlier and produce false last-edit advice.
  - Fix: define one persisted total order for remedy and recurrence events, including ties, and use it for matching, selection, rendering, and tests
- HIGH `[collapsed-remedy-history]`: The Overview, Architecture, Input, step 1, step 5, and the first and fourth acceptance criteria require a later recurrence to be traceable to its remedy, but they do not require the remedy event to retain its original finding evidence and source report through collapse. `convergence_diagnosis:build_collapsed_completeness_passes` replaces a collapsed pass’s findings and timestamp with the newest snapshot, while `_merge_collapse_annotations` keeps only one annotation per finding id, so a changed re-audit can become the evidence for an older remedy.
  - Fix: retain each remedy event with its original finding evidence and source-report identity through collapsed history, then match and render the closest qualifying prior event rather than a replacement snapshot
- HIGH `[qualified-remedy-evidence]`: The Overview, Problem statement, Architecture, Input, steps 2, 3, and 5, the apply-path Risk, Testing, and the first two acceptance criteria treat a deliberately declined remedy as evidence for a “likely-bad-fix re-check-last-edit” advisory, although a decline creates no edit to re-check. `Annotation` only records status, note, and halt reason, and `completeness_apply_parallel:annotation_status` maps generated `NOT-APPLICABLE` outcomes to `skip`, so the plan also leaves generated, failed, halted, and legacy records able to look like causal evidence.
  - Fix: record all dispositions, but define one fail-closed qualification rule so only a real, attributable applied remedy can trigger the advisory; declines and non-remedy records remain visible but never causal evidence
- HIGH `[same-issue-identity]`: The Architecture, Input, steps 4 and 5, identity-fallback Risk, Testing, and third acceptance criterion say equal id is a “fast path” before anchor, skeleton, and title matching, but do not say that id alone is insufficient or that a skeleton/title must be usable. `convergence_diagnosis:_matches` also treats shared step focus as a match, and `_title_ratio("", "")` succeeds, so a reused id, same-step finding, or empty identity can create an unrelated bad-fix advisory.
  - Fix: define a dedicated conservative comparator for this advisory: id only narrows candidates, then require a usable anchor, skeleton, or title under the stated order while leaving existing recurrence matching unchanged
- MEDIUM `[recurrence-history-boundary]`: The Architecture’s generic “saved audit annotations,” step 5’s “earlier remedy notes,” step 6, Testing, and the acceptance criteria do not choose which report stream and recurrence window may produce advice. `convergence_diagnosis:HISTORY_KINDS` admits completeness, detail-reconcile, and run-reconcile reports, while `build_collapsed_completeness_passes` and `classify_edit_drift` use completeness-only history; either interpretation changes when the advisory appears.
  - Fix: define the eligible report kinds, stage compatibility, collapse boundary, minimum history, and newest-finding state for provenance matching
- MEDIUM `[hand-remedy-selection]`: Step 3 says it replaces only the “chosen audit sidecar,” but its intent, Input, and the every-path acceptance criterion do not define how a hand record identifies one saved audit and one finding, or what happens for missing or ambiguous selection. `review_persistence:update_annotation` needs an exact recommendation id, and the existing completeness flow distinguishes the newest audit from an explicitly pinned one; a free-form or misdirected record cannot support later matching reliably.
  - Fix: define an unambiguous hand-record selection contract for the saved audit and finding, with no sidecar mutation on invalid or conflicting selection
- MEDIUM `[sidecar-write-lock]`: Step 1 and step 3 promise atomic sidecar replacement, and Risks promise durable provenance, but `review_persistence.update_annotation` performs an unlocked load–modify–replace operation. Atomic replacement cannot prevent a concurrent interactive, parallel, or hand-record write from dropping another remedy event.
  - Fix: Require one shared whole-update serialization rule for every remedy-note writer while retaining atomic durable replacement.
- HIGH `[matched-recurrence-precedence]`: Step 6 says operators re-check the last remedy “before treating a matched recurrence as evidence that the plan is mis-decomposed,” while `convergence_diagnosis:render_diagnosis` independently emits `_structural_recurrence_lines` telling them to “consider re-splitting the step or `plan-tool scope-out`.” Overview, Architecture, steps 5–6, and acceptance criteria 1, 4, and 5 never define which recommendation wins for the same matched recurrence.
  - Fix: define that a qualifying bad-fix match suppresses or explicitly defers only its matching structural recommendation while unrelated recurrence advice remains unchanged
- MEDIUM `[remedy-event-idempotency]`: Step 1’s history across repeated annotations, step 2’s parallel writer, step 3’s hand-record writer, and step 5’s choice of the last remedy do not distinguish a persistence retry from a new rewalk or a new remedy. Duplicate retry events can become the apparent last edit and produce misleading advice.
  - Fix: define remedy-event identity and deduplication rules across every writer so only distinct remedies affect ordering and matching

## Conceptual completeness — reported, not auto-applied

Coverage gaps in the plan's own ideas are reported for visibility in this bare-plan audit. Apply actions for this axis are withheld until a complete detail bundle exists, so these findings are informational for now.

- MEDIUM `[sidecar-write-lock]`: Step 1 and step 3 promise atomic replacement, and Risks promise durable provenance, but atomic replacement alone does not protect two whole-file read–modify–write operations from dropping one another’s notes. `review_persistence:update_annotation` loads then rewrites the full sidecar; the existing mutation-lock set covers `completeness-apply` but cannot cover the new record command until step 3 adds it.
  - Fix: require every remedy-note writer, including hand recording, to use the repository mutation lock and prove contention leaves the selected sidecar unchanged
- MEDIUM `[remedy-event-idempotency]`: Step 1’s ordered history across repeated annotations, step 2’s parallel writer, step 3’s hand-record writer, and step 5’s choice of an earlier remedy do not distinguish a persistence retry from a genuinely new rewalk or remedy. Risks, Testing, and the acceptance criteria do not lock this down, so valid implementations can either duplicate one event or erase a later independent remedy and change which edit receives advice.
  - Fix: Add an acceptance criterion that defines idempotent retries separately from new accepted rewalks and preserves each genuine remedy event exactly once in the ordered history.
