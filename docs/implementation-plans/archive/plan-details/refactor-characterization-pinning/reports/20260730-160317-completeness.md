- HIGH `[sandbox-cleanup]`: Sandbox teardown cannot work as described in step 3 (`Add the throwaway pre-change sandbox: worktree at a SHA, copy test files in, always clean up`): copying the post-change test files in makes the worktree unclean **by design**, and `gitcommit.worktree_remove` refuses an unclean worktree unless `force=True` is passed. The Risks entry's fallback — "removal must tolerate that rc and fall through to `worktree prune`" — does not recover, because `git worktree prune` only drops admin entries whose **directory is gone**, and here the directory still exists. Every sandbox therefore leaks both a directory and a `$GIT_DIR/worktrees` entry, contradicting the criterion "Worktrees are removed on every path, including failures".
- HIGH `[files-placeholder-plan-gate]`: Adding a `{files}` placeholder to `test_command` in step 2 (`Expand test_command with a files placeholder and reuse the test-gate runner for the sandbox`) breaks the plan-level test gate, which executes the field verbatim: `launcher.run_step` calls `_run_test_gate(plan.test_command, repo_root)` with `shell=True`. A single-word brace is not expanded by the shell, so pytest receives a literal `{files}` path, exits with a usage error, and the step is blocked from advancing. Any plan that adopts the placeholder to enable this check disables its own gate.
- HIGH `[runner-import-cycle]`: The plan creates a second import cycle it never names: step 3 puts the check in `plan_tool/characterization_check.py`, which `plan_tool/launcher.py` imports, while step 4 (`Run the copied tests in the sandbox and tell a failure apart from an uncollectable file`) runs them "through the **existing** test-gate runner", and that runner — `_run_test_gate` — is defined in `plan_tool/launcher.py` itself. Step 4's `files:` lists only `plan_tool/characterization_check.py`, so the module would import back into `launcher` at module scope. The Import-layering paragraph resolves only the `plan_tool.cli` cycle and is silent on this one; the Testing section's "the pre-change test run itself must be seam-injected" hints at the resolution but never states it as the layering rule.
- MEDIUM `[no-new-git-plumbing-fence]`: The Out-of-scope fence — "no new primitive, **no new subprocess call site**" with a single named exception for `worktree_add`'s detached option — contradicts step 6 (`Capture the pre-change commit at step start and decide whether the check can run`), which needs `git rev-parse HEAD`. No reusable rev-parse helper ships: `gitcommit.py` has none, and the only call sites are private ones inside `plan_tool/scenario_capture.py` and `plan_tool/cli/completeness_apply_parallel.py`. The clean-tree half of the same step is the opposite case — `gitcommit.working_tree_dirty` and `launcher._git_changed_paths_or_none` already ship it, yet the Architecture describes writing the probe fresh.
- MEDIUM `[non-empty-target-removal]`: Treating `NON_EMPTY` as "remove-then-recreate, never reuse" (Architecture, mechanism item 3, implemented by step 3) inverts what `worktree.classify_target` documents: it returns `NON_EMPTY` for an **unreadable** directory too, explicitly "fail safe, so a caller never overwrites a dir it can't inspect". The derived path lives in the shared workspace base outside the repo, where an unrelated directory can sit, so the rule as written authorizes deleting a directory the check cannot confirm is its own. `NOT_A_DIR` gets no stated handling at all.
- MEDIUM `[pytest-exit-codes]`: The acceptance criterion "pytest separates them by exit code (`2` for a collection/usage error, `1` for test failures)" is wrong about pytest's table, and step 4 (`Run the copied tests in the sandbox and tell a failure apart from an uncollectable file`) is built on it: pytest uses `2` for interrupted (which is what a collection error raises), `4` for a usage error, and `5` for no tests collected. Under the plan's stated rule a copied file that collects nothing returns `5`, reads as "did not pass against pre-change source", and produces exactly the false alarm the design says costs more than a miss.
